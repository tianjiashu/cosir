# 独立复核简报模板

派给复核子 Agent。分两轮发送：第一轮**不附**作者的等价论证，让复核者独立找反例；拿到第一轮结论后，再发第二轮。

## 第一轮

```markdown
你是代码精简变换的独立复核者。下面每个变换都声称「不改变行为、不引入逻辑缺陷」。
你的任务是尽力找出反例：在什么输入、状态、时序或调用路径下，改动前后的行为会不同。

## 判定依据
- 行为边界：<粘贴标准 §3>
- 缺陷风险点：<粘贴标准 §5.3 表格>
- 项目画像要点：<粘贴与本批变换相关的画像维度，如信任边界、运行拓扑>

## 待复核变换
### <编号>：<变换编号，如 F1>，<文件:符号>
<diff>
相关代码：<被调用方、调用方、类型定义的位置或片段>

（每个变换重复以上结构）

## 要求
- 自己阅读代码，不要假设改动是正确的。
- 对每个变换，逐项检查 §5.3 中相关的风险点。
- 防御类变换：找出「被删除的防御所守护的情形」能否在任何调用路径上发生。
- 只读，不修改任何文件。

## 输出（每个变换一段）
- 结论：成立 / 存疑 / 有反例
- 依据：检查了哪些风险点、哪些调用路径；有反例时给出具体输入或时序
```

## 第二轮

```markdown
下面是作者对这些变换的等价论证。请对照你第一轮的结论：
- 论证中是否有你没考虑到、但成立的理由？据此可以修正结论。
- 论证中是否有遗漏的风险点或未经证实的假设？

<逐个变换粘贴作者的等价论证>

输出：每个变换的最终结论（成立 / 存疑 / 有反例）与理由。
```
