## 发现的缺陷（未修复，建议另行处理）

1. `ReadonlyThread` 不传 `workspaceId`，工作台中子 Agent 只读线程里的图片（用户图片、`read_image`、浏览器截图）解析不出地址。
2. `supervisor.restart()` 会重置 `shuttingDown`：若在 `stop()` 宽限期内收到 restart IPC，会把正在退出的后端重新拉起（实际几乎不可能触发）。
3. `frontendLog` 在 `error` 为 `Object.create(null)` 一类值时会 reject，而 154 处调用方没有 `.catch`。
4. `terminal-tool.tsx:82` 按工具名 `execute_terminal` 分支，违反「禁止按工具名写渲染分支」；根因在 `terminal-session` 条目未按 `presentation.variant` 命中。

## 标准与 skill 修订建议

1. **§6 / SKILL 中止条件**：「基线静态检查失败即停」过严。本轮 lint 的 50 个错误都在工具脚本与测试的配置上，与等价性无关。建议区分：测试失败必须停；静态检查有既有告警时以告警数为基线，按 G5「不增加」验收。
2. **SKILL 流程**：缺少「只审查、不执行」的使用方式。本轮停在关卡一，计划存放在 `.simplification/plans/`；建议在 skill 中正式定义这种模式与计划文件的位置。
3. **detection-scripts 演进经验**：基于类型的守卫检测，在类型系统对下标访问持乐观假设的语言里，会把对下标结果的判空误报为多余；应先让检测按「下标可能缺失」的语义运行。可作为附录 A 的第一条实践案例。
4. **SKILL 第 3 阶段**：范围很大时，人工阅读可以按区域并行交给子 Agent，主 Agent 必须抽查复核每份结果。建议写明这种做法与复核要求。
