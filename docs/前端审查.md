结论：InputBar 存在一个会阻断新任务发送的 P0 缺陷，另有草稿丢失、附件功能未接入和可访问性问题。样式也值得优化。

### 必须优先修复

1. **新任务首条消息无法发送（P0）**

发送新任务时：

- `InputBar` 调用 `createTask`；
- `createTask` 设置乐观任务 ID；
- `replaceTask` 判断条件错误：用当前 active ID 与真实 ID比较，永远无法完成 active ID 转正；
- 随后调用的 `createTurn` 仍捕获着旧的 `activeTaskId=null`，直接返回“未选择任务”。

相关位置：

- [useTask.ts:313](H:/coding-agent/apps/desktop/src/hooks/useTask.ts:313)
- [useTask.ts:324](H:/coding-agent/apps/desktop/src/hooks/useTask.ts:324)
- [useTask.ts:334](H:/coding-agent/apps/desktop/src/hooks/useTask.ts:334)
- [useTask.ts:172](H:/coding-agent/apps/desktop/src/hooks/useTask.ts:172)
- [taskStore.ts:733](H:/coding-agent/apps/desktop/src/stores/taskStore.ts:733)

这会导致 InputBar 和 NewTaskPage 创建出任务容器后，首轮 turn 创建失败。

建议让 `createTurn` 接收明确的 `taskId`，并让 `replaceTask(oldTaskId, task)` 在当前 active ID 等于 `oldTaskId` 时原子切换到真实 ID。

2. **发送失败时草稿可能永久丢失（P1）**

发送前会清除 store 草稿，但失败时只恢复本地输入框，没有恢复 `taskStore.drafts`：

- [useSendInput.ts:132](H:/coding-agent/apps/desktop/src/components/layout/useSendInput.ts:132)
- [useSendInput.ts:152](H:/coding-agent/apps/desktop/src/components/layout/useSendInput.ts:152)

当前页面看起来恢复了，但切换任务、刷新或组件重挂载后草稿会消失。

3. **异步失败会覆盖用户的新输入（P1）**

发送请求尚未完成时，用户仍可继续输入；如果旧请求失败，`local.restore()` 会无条件覆盖新输入：

- [InputBar.tsx:135](H:/coding-agent/apps/desktop/src/components/layout/InputBar.tsx:135)
- [useSendInput.ts:152](H:/coding-agent/apps/desktop/src/components/layout/useSendInput.ts:152)

任务切换期间还可能把旧任务草稿恢复到新任务输入框。应加入 taskId / draft revision 检查，只在输入框仍为空且版本未变化时恢复。

### 其他问题

4. **附件功能目前是半成品**

InputBar 只有占位按钮，没有 `onClick`：

- [InputBar.tsx:178](H:/coding-agent/apps/desktop/src/components/layout/InputBar.tsx:178)

但工作树中已有未接入的 `useAttachmentInput`、`AttachmentChip` 和附件测试。该测试当前 10/10 失败，主要因为测试期待 `ComposerPrimitive` 和附件 UI，而生产代码仍是原生 `<Input>`。

5. **附件和语音按钮缺少无障碍名称（P2）**

Plus 和 Mic 按钮没有 `aria-label`，读屏只能识别成无名称按钮：

- [InputBar.tsx:178](H:/coding-agent/apps/desktop/src/components/layout/InputBar.tsx:178)
- [InputBar.tsx:224](H:/coding-agent/apps/desktop/src/components/layout/InputBar.tsx:224)

6. **无活跃任务时仍显示 `0 / 0 上下文`**

空会话底部显示“上下文已使用 0.0% · 0 / 0 上下文”，信息没有意义。建议无 `activeTaskId` 时隐藏，或改成“发送后显示上下文用量”。

### 样式优化建议

当前是“底部横条 + 输入框 + 外置按钮”的结构，视觉略碎。建议：

- 使用统一的 composer 卡片：`rounded-xl border bg-card p-2 shadow-composer`；
- Plus、输入框、发送按钮放进同一表面；
- 外层减少 `border-t`，改为 `pt-2 pb-4`；
- ContextUsageRing 放到卡片下方并弱化颜色；
- 已有 `react-textarea-autosize`，建议将单行 `Input` 改为自动增高多行输入，支持 `Shift+Enter` 换行；
- 清理 `Input` 上无效的 `resize-none`；
- 占位功能按钮应暂时 `disabled`，否则用户会认为按钮已可用。
