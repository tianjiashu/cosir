# Delegate Subagent Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a production-grade `delegate_task` tool that lets a parent Agent delegate review, analysis, and coding work to child AgentProfile-based agents while preserving observability, checkpoint/recovery auditability, SSE visibility, and frontend timeline clarity.

**Architecture:** The feature reuses the existing AgentProfileRegistry, AgentRuntime, workflow, ToolSystem, RuntimeEventBus, TurnService, and Langfuse integration. `tools` owns only the tool contract and executor protocol; `core/delegation` owns child execution; `service/delegation` owns policy, records, and persistence orchestration; the desktop client consumes generated shared event types and renders delegation through the existing timeline pipeline.

**Tech Stack:** Python 3.11 / FastAPI / SQLAlchemy / SQLite / LangGraph runtime / pytest / uv; React + TypeScript + Vite / Zustand / shadcn-ui / Tailwind / Vitest.

## Global Constraints

- 第零铁律：所有取舍以“方便项目长期稳定迭代”为最终目标，禁止为了小改动留下并行运行时、全局 mutable handler 或不可观测黑盒。
- Backend dependency direction must remain: `api -> core/service`, `core -> service/tools/models/config/trace_infra`, `service -> storage/models/config/trace_infra/tools`, `storage -> models`, `tools -> config/models/utils/trace_infra`.
- `tools` must not import `service` or `core`; `service` must not import `AgentProfile`; `core/observability` remains the only Langfuse third-party dependency boundary.
- New Python functions/methods must have complete Chinese docstrings with 参数 / 返回 / 异常 / 副作用 and typed signatures.
- Logs must use `from app.config.logging.logger import log`; stable English snake_case event keys; Chinese `msg`; business IDs inside `data`.
- Shared frontend event types are generated by `scripts/generate_runtime_event_ts.py`; do not hand-edit `apps/shared/ts/events.ts`.
- First version must support three child agents: `delegate_reviewer`, `delegate_analyst`, `delegate_coder`, selected by `child_agent_id`; `delegation_type` is a label, not the source of permissions.
- Effective child tools are `requested_tools ∩ parent.allowed_tools ∩ child.allowed_tools ∩ system_policy_allowed_tools`.
- Default delegation depth is 1 and default parent concurrency is 1; child profiles must not be allowed to re-delegate in v1.
- First version SSE decision: parent timeline receives delegation summary events; child turn is observable through a subscribe-only child turn stream.

- Tool batches run from `tools_node` through `asyncio.to_thread(...)`; the concrete `ChildAgentRunner` may bridge async child runtime with `asyncio.run(...)`, and must fail fast with a deterministic `DelegationResult(status="failed", error="delegation_runner_event_loop_thread")` if it is ever called from an already-running event loop thread.

- Depth v1 is conservative: a top-level parent turn has depth `0`; a turn with `parent_turn_id` has depth `1`. `DelegationPolicy.max_depth=1` therefore rejects grandchildren.
- Active child count is the number of delegations for the parent turn with status `pending` or `running`.
- The child profile must never receive `delegate_task`; `ChildAgentProfileBuilder` already enforces narrowed tools and profile immutability.
- `DelegationService` owns status persistence and parent-turn runtime events:

- `ChildAgentRunner` consumes `AgentRuntime.run_agent(child_profile)`: return completed on `EventType.RUN_FINISHED`, failed on `EventType.RUN_FAILED` or exception, cancelled on `EventType.RUN_CANCELLED`. Use payload text if available; otherwise return a deterministic short summary/error.
- `AgentRuntime._build_operations(...)` constructs the per-turn executor with the current `agent_profile`, current task/workspace/turn services, registry, scheduler tool names, and `ChildAgentRunner(self.run_agent)`.
