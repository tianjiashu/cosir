





**Context-Folding（上下文折叠）**，不是普通的“上下文压缩/摘要”。

我核到的出处是 ByteDance Seed 等人的论文/项目页：**“Scaling Long-Horizon LLM Agent via Context-Folding”**，作者单位包含 **ByteDance Seed**、CMU、Stanford。项目页在这里：[context-folding.github.io](https://context-folding.github.io/)。

它的核心思想是：

> Agent 不再把所有历史线性塞进一个越来越长的 context，而是能主动创建局部子轨迹，完成后把中间过程折叠掉，只把结果摘要带回主线程。

可以理解成一种 **branch / return / fold** 机制：

1. **Branch**：遇到局部子任务时，开一个临时上下文分支。
2. **Execute**：在分支里搜索、尝试、调用工具、推理。
3. **Return**：子任务完成后回到主线程。
4. **Fold**：把分支里的大量中间步骤折叠成一个紧凑摘要，只保留对后续有用的信息。

它和普通 summarization 的区别在于：

- 普通上下文压缩：通常是“历史太长了，整体做摘要”。
- Context-Folding：更像运行时结构设计，让 Agent 知道哪些步骤属于一个局部任务，任务结束后主动折叠。
- 重点不是“压缩文本”，而是“管理工作上下文结构”。

这对 coding-agent 很相关，尤其是长任务：

- 调试某个失败测试时，可以开一个折叠分支。
- 分支内读日志、查调用链、尝试修复思路。
- 结束后只回填：“失败原因、已验证事实、修改建议、仍需注意的文件”。
- 中间反复搜索、无效假设、长日志都不继续污染主上下文。

它和你项目里已经规划的 **context compaction / subagent / checkpoint** 是同一方向，但粒度更主动、更结构化。你现在的架构如果要吸收这个思想，我会把它看成：

```
Context compaction = 底层压缩能力
Subagent / child run = 分支执行能力
Context-Folding = 运行时策略层：何时 branch，何时 fold，fold 后保留什么
```

论文里还提出了 **FoldGRPO**，用强化学习训练模型学会何时折叠、如何折叠。工程第一版不一定要训练模型，可以先做规则驱动版本：按子任务结束、工具调用密度、token 阈值、Plan item 完成等触发 folding。
