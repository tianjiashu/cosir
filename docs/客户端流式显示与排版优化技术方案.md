# 客户端流式显示与排版优化技术方案

> 在已落地的 `TerminalCallCard` 浅色紧凑样式（折叠态单行截断 `text-xs`、展开态完整命令换行）与既有 `ChatPanel` rAF 节流滚动之上，系统解决客户端「流式显示 / 字号 / 行距 / 超长会话性能」四类痛点。本文档整合前期讨论的全部优化点（流式 caret、字号行距统一 token、流式期代码块折叠、思考块流式可见、timeline 虚拟滚动、统一排版 token），给出**一步到位**的落地方案。
> 依赖策略（沿用项目约定）：排版/流式优化**零新依赖**——基于既有 `tailwindcss` + `lucide-react` + shadcn 原语手写；**timeline 虚拟滚动引入 `@tanstack/react-virtual`**（动态高度原生支持、体积 ~10KB 非 MB 级，不触发「须上报决策」红线，但立项时同步告知）。
> 改动规模：中/大（前端约 8 文件：AgentMessage / ThinkingBlock / CodeBlock / TerminalCallCard / UserMessage / ChatPanel / 新增 `messageTypography.ts` + `useTimelineVirtualizer.ts` + 扩展既有测试），按 `AGENTS.md` 第八节须走**独立审查 Agent + 独立测试 Agent** 闭环。

## 一、背景与目标

### 1.1 起点

客户端桌面端当前已具备基本流式能力：`ChatPanel` 通过 rAF + 200ms 节流滚动跟随新消息；`AgentMessage` 渲染流式 markdown 正文；`ThinkingBlock` 渲染思考块；`CodeBlock` / `TerminalCallCard` 渲染代码与命令输出。但在「流式观感、字号层级、行距一致性」三个维度存在已知差距，已在前期讨论中梳理：

1. **字号行距不统一**：正文 `text-sm leading-relaxed`、代码块 `text-xs`、思考块 `text-xs`，同一卡片内层级跳变且未形成稳定规范。
2. **流式无「实时生成」感知**：流式期间 markdown 频繁变化，段落高度抖动、代码块反复重建、无稳定光标，用户难以感知「正在生成」。
3. **流式期长输出不可控**：超长代码块在流式期间整段重建 DOM 并把对话推得很长；行内超长路径（如 `FileLink`）未处理换行，可能撑破布局。
4. **思考过程不可见**：`ThinkingBlock` 仅在「完整内容」时渲染，流式思考过程中看不到渐进内容，用户只能看到最后出现的一块。

### 1.2 目标

1. **统一排版 token**：抽 `MessageTypography` 约定（字号 / 行距 / 颜色 / 间距），所有消息组件复用，消除各写一套 `text-sm leading-relaxed` 的漂移。
2. **流式 caret**：`status === running` 时在正文末尾渲染稳定闪烁光标，结束移除，提升「实时生成」感知，对齐 Codex 风格。
3. **流式视觉稳定性**：流式期间容器加 `min-h` / `min-w` 避免塌缩；代码块在流式期折叠 + 「展开完整代码」按钮。
4. **思考块流式可见**：流式期直接展示累积中的思考文本（带 caret），结束后再允许折叠。
5. **富文本排版加固**：行内代码 / 文件路径 `break-words` 防撑破；明确正文 `leading-7`（28px）让长文透气。
6. **timeline 虚拟滚动**：超长会话（几百 turn）下，只渲染视口内 turn + 少量 overscan 缓冲，回收视口外 DOM，把 O(总 turn 数) 的 DOM 降到 O(视口内 turn 数)；动态高度由 `@tanstack/react-virtual` 自动测量缓存；配套解决卡片展开态持久化避免滚出视口丢失。

设计取舍（已与用户确认「先写文档、一步到位」）：

- **统一 token 而非各组件硬编码**：所有消息组件复用 `MessageTypography` 约定，避免后续再漂移。
- **手写 caret（CSS animation）而非引入动画库**：caret 是单字符 + `animate-pulse` 级别，无需引入库。
- **流式期代码块折叠而非交互式终端**：当前是只读回放卡片，交互式终端属独立大模块（PTY + xterm.js），不混入本期。
- **虚拟滚动用 `@tanstack/react-virtual` 而非 `react-window` 手写测量**：`TurnTimeline` 高度完全动态（流式文本增长、代码块折叠/展开、工具卡片展开均变高），`react-window` 的 `VariableSizeList` 需手动维护高度缓存且对动态变高不友好；`@tanstack/react-virtual` 的 `useVirtualizer` + `measureElement` 自动测量并缓存每项真实高度，天然适配流式变高，`~10KB` 非 MB 级。
- **打字机动画列为以后做**：与 SSE 增量重复、对长文性能差、破坏可访问性，不本期启动；交互式终端同为独立大模块不混入本期。

## 二、现状与缺口

### 2.1 现状（已通读前端渲染链路，行号为撰写时快照，落地前以 `read_file` 实际为准）

| 组件 | 排版现状 | 流式处理现状 | 缺口 |
|---|---|---|---|
| `AgentMessage` | 容器 `text-sm leading-relaxed`；段落 `whitespace-pre-wrap` | 整段重渲染，无 caret | 无实时生成感知；字号偏大 |
| `ThinkingBlock` | `text-xs` 独立块 | 仅完整内容时渲染 | 流式思考不可见 |
| `CodeBlock` | `<pre>` `text-xs`；`whitespace-pre-wrap` | 每次增量重建 DOM | 超长代码把对话推长；行内未 break |
| `TerminalCallCard` | 折叠 `text-xs truncate`、展开 `whitespace-pre-wrap break-all` | 输出一次性回填 | 已优化（见 `TerminalCallCard` 改动） |
| `UserMessage` | 独立气泡排版 | 非流式（用户输入即全量） | 与 Assistant 排版未统一 token |
| `ChatPanel` | rAF + 200ms 节流滚动 | 跟随新消息滚动（scrollIntoView） | 滚动策略已具备；但所有 turn 的 DOM 全部常驻，超长会话下布局/内存 O(总 turn 数) |

### 2.2 缺口

1. 无统一 `MessageTypography` token，各消息组件字号 / 行距 / 颜色各自为政。
2. 流式期无 caret，无 `min-h` / `min-w` 防塌缩，长文高度抖动。
3. 流式期超长代码块不可折叠，DOM 反复重建且推长对话。
4. 思考块流式期不可见，用户感知断层。
5. 行内超长路径 / 代码未 `break-words`，可能撑破布局。
6. **超长会话 DOM 爆炸**：`ChatPanel` 第 136-142 行 `timelineTurns.map(... <TurnTimeline/>)` 把所有 turn 全部挂载，即使历史 turn 因 memo 不重渲染，DOM 节点仍常驻内存；几百 turn 时浏览器 layout/paint 成本随总条目数线性增长，无虚拟回收。

## 三、设计方案

### 3.1 统一排版 token：`MessageTypography`

新增约定（建议落地位置：`src/components/chat/messageTypography.ts` 或 `tailwind.config.ts` 扩展 theme），作为所有消息组件的字号 / 行距 / 间距单一事实来源：

```ts
// 消息排版 token：所有消息组件复用，禁止各写一套 text-sm leading-relaxed
export const MessageTypography = {
  body: "text-[13px] leading-7", // 正文：介于 sm(14) 与 xs(12) 之间，行距 28px 透气
  secondary: "text-xs leading-5", // 思考块 / 代码块 / 元信息：稳定次要层级
  code: "text-xs leading-5 font-mono", // 等宽代码
  caret: "inline-block w-[1px] h-[1em] align-text-bottom animate-pulse bg-foreground/70", // 流式光标
} as const;
```

- **正文**用 `text-[13px] leading-7`：比当前 `text-sm` 略小、行距明确，长文更透气且不与 `text-xs` 次要信息跳变过猛。
- **次要信息**统一 `text-xs leading-5`：思考块 / 代码块 / 元信息形成稳定层级。
- **caret** 用 CSS `animate-pulse` 实现闪烁，零依赖。

### 3.2 流式 caret（`AgentMessage`）

在 `AgentMessage` 渲染正文时：

- 读取当前 turn / 消息的 `status`（来自 `turnStore` / projector 的 running 信号）。
- 当 `status === "running"` 且正文非空时，在末尾渲染 `<span className={MessageTypography.caret} />`。
- 流式结束（`status` 变为 success / error）移除 caret。
- 容器加 `min-h-[1.5em]`（避免首字到达前塌缩）与 `min-w-0`（避免 inline 元素撑破 flex）。

> 注：caret 仅作「生成中」视觉锚点，不参与可访问性朗读（加 `aria-hidden`）。

### 3.3 流式期代码块折叠（`CodeBlock`）

在 `CodeBlock` 增加「流式期折叠」能力：

- 新增 props `streaming?: boolean`（由 `AgentMessage` 透传当前消息 running 状态）。
- 当 `streaming` 且代码行数 / 字符数超过阈值（如 `> 12` 行或 `> 600` 字符）时，默认折叠为 `max-h-48 overflow-hidden` + 底部「展开完整代码」按钮；非流式期保持原样（或按既有截断逻辑）。
- 折叠态底部渐变遮罩 + 「展开完整代码」点击展开，避免超长代码把对话推得很长。
- `<pre>` 内行内代码 / 路径加 `break-words`（或 `break-all` 仅限路径），防超长 token 撑破布局。

### 3.4 思考块流式可见（`ThinkingBlock`）

`ThinkingBlock` 渲染逻辑调整：

- 接收 `streaming` 信号；流式期直接渲染累积中的 `content`（带 caret），不等待「完整内容」事件。
- 流式结束后再挂载「折叠 / 展开」交互（与 `TerminalCallCard` 的 `expandable` 一致），避免流式期反复切换折叠态造成抖动。
- 流式期思考块用 `MessageTypography.secondary` 排版。

### 3.5 富文本排版加固

- `AgentMessage` 正文容器统一 `MessageTypography.body` 替代散落 `text-sm leading-relaxed`。
- `UserMessage` 复用同一 token（气泡内文字与 Assistant 正文同字号行距，避免对比突兀）。
- 行内代码（markdown `code`）、`FileLink` 路径统一 `break-words`。

### 3.6 Timeline 虚拟滚动（`ChatPanel` + `@tanstack/react-virtual`）

**现状落点**：`ChatPanel` 第 136-142 行 `timelineTurns.map((turn) => <TurnTimeline .../>)`，外层 `<ScrollArea>` + `space-y-4` 的 div。turn 级 memo 已解决「重投影卡顿」，但所有 turn DOM 常驻。虚拟滚动替换这个 `map`，只渲染视口内 turn + overscan 缓冲。

**核心难点：动态高度**。每个 `TurnTimeline` 高度完全动态：流式文本增长、代码块折叠/展开、工具卡片展开均改变高度，且用户展开历史卡片也变高。不能用固定高度方案，必须用动态高度虚拟列表。`@tanstack/react-virtual` 的 `useVirtualizer` + `measureElement` 自动测量并缓存每项真实高度，天然适配。

**方案（聚焦改动）**：

1. **新增 `src/components/layout/useTimelineVirtualizer.ts`**：封装 `useVirtualizer`，入参为 scroll 容器 ref、`timelineTurns` 数组；返回 `virtualItems` / `totalSize` / `measureElement`；`estimateSize` 给合理初值（如 `320`），`overscan` 设 `4-6` 项缓冲；`getScrollElement` 指向滚动容器。
2. **`ChatPanel` 改造**：
   - 滚动容器从 `<ScrollArea>` 改为原生 `div`（`ref={scrollRef} className="flex-1 overflow-y-auto scrollbar-thin"`），避免 radix `ScrollArea` 的自定义视口与 virtualizer `getScrollElement` 不兼容。
   - 用 `useTimelineVirtualizer(scrollRef, timelineTurns)` 得到 `virtualItems` / `totalSize`。
   - 渲染结构：`外层 div style={{ height: totalSize, position: "relative" }}` 撑出正确滚动条 → 每个 `virtualItem` 包 `div style={{ position:"absolute", top:0, left:0, width:"100%", transform: translateY(virtualItem.start) }}` 并挂 `ref={virtualizer.measureElement}` 让库自动量高 → 内部渲染 `<TurnTimeline>`。
   - 保留 `space-y-4` 间距：改用每项底部 `paddingBottom` 或在外层 wrapper 用 `marginBottom`，因绝对定位无法用 `space-y`，需在 measureElement 测出的高度里包含间距（或在 item 内层加 `pb-4`）。
3. **流式自动滚动适配**：现有 rAF + 200ms 节流滚动（第 96-105 行）的 `scrollIntoView` 改为 virtualizer 的 `scrollToIndex(virtualItems.length - 1, { align: "end" })`；且**仅当用户已在底部时跟随**（记录 `isAtBottom` 状态，监听 scroll 距底阈值），避免用户看历史时被强制跳转。流式期高度变化由 `measureElement` 自动重测，滚动锚点保持稳定。
4. **展开态持久化（必须配套）**：虚拟列表回收视口外节点后，历史 turn 重挂载时本地 UI state（如 `TerminalCallCard` / `ToolCallCard` 的 `isOpen`、代码块「展开完整代码」）会丢失 → 用户展开的历史卡片滚出视口再回来变回折叠。**解法**：把卡片展开态提升到 `useEventStore` 或 `turnStore`（以 `eventId` 为 key 的 `Set<string>` 持久化展开集合），`TurnTimeline` / 卡片从 store 读取 `expandedSet.has(eventId)`，而非本地 `useState`。这样重挂载能恢复展开态。

**边界与注意**：

- `measureElement` 在流式期频繁变高时会触发重测与 offset 修正，virtualizer 内部已处理，无需手写；但高频重测有成本，配合现有 rAF 节流（流式增量已每 200ms 一次）可接受。
- 窗口 resize / 字体加载完导致高度变化：`@tanstack/react-virtual` 的 `measureElement` 用 `ResizeObserver`，自动重测。
- 锚点跳转（如「跳到某 turn」）后续可加 `scrollToIndex(turnIndex)`。

## 七、风险与注意事项

- **caret 与 SSE 增量**：caret 是纯 CSS 视觉锚点，不参与文本渲染，不会与流式增量冲突。
- **`min-h` 防塌缩**：仅在容器无内容时生效，有内容后由内容撑开，不影响正常排版。
- **代码块折叠阈值**：阈值（行数 / 字符数）须可配置，避免误伤短代码；非流式期保持原样。
- **可访问性**：caret 加 `aria-hidden`；`prefers-reduced-motion` 下 caret 不闪烁（CSS media query 关闭 animation）。
- **虚拟滚动依赖**：引入 `@tanstack/react-virtual`（~10KB，非 MB 级），立项时同步告知；不引 `react-window`（动态高度支持弱、需手维护高度缓存）。
- **展开态持久化是虚拟滚动的硬配套**：不提升到 store 则历史卡片滚出视口再回来会丢失展开态；必须随虚拟滚动一起落地（清单第 9 项）。
- **`ScrollArea` 兼容性**：虚拟滚动场景改用原生 `overflow-y-auto`，避免 radix `ScrollArea` 自定义视口与 virtualizer `getScrollElement` 不兼容。
- **流式期高度抖动**：`measureElement` 用 `ResizeObserver` 自动重测，配合现有 rAF 节流可接受；`isAtBottom` 跟随避免强制跳转打断用户看历史。
