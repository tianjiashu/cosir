# 本地应用能力清单（补 / 删）

**文档性质**：清单，不是技术方案。每条只回答「要什么 + 为什么」，实现步骤另立计划文档。

**核对日期**：2026-09-01（结论基于当次代码事实，与代码冲突时以代码为准）

## 0. 边界定义

避免清单无限膨胀，先划界：

- **控制面** = 除「对话运行」之外的一切宿主职责：管进程、管数据放哪、管端口、管用户感知。
- 凡是要改 `core` / `service` / `tools` 的，不属于控制面，不在本清单。
- 「对话链路」（Transport / canonical state / revision 订阅 / Agent Runtime）**已可运行，本清单不动它**。

清单依赖的几条硬事实：

| 事实 | 状态 |

## 第一部分：需要补的

### A1 梯队一 — 不补会出事

| # | 项 | 理由 |
|---|---|---|
| A1.1 | **单实例守卫** | 最易忽略、最致命。SQLite 明文存储 + 常驻 kernel，双开 = 两个后端抢同一 SQLite 文件 + 两份 kernel 抢索引。不是体验问题，是数据损坏风险。收益/成本比最高，列第一 |
| A1.2 | **后端 sidecar 生命周期** | 拉起 / 就绪探测（读 bootstate `ready`）/ 优雅停机 / 退出码感知。当前完全靠人手 |
| A1.3 | **崩溃策略（含"禁止无脑重启"）** | 读 bootstate `failed` + 日志文件定位原因；要退避 + 次数上限 + 用户可见失败界面（含"查看日志"入口）。crash loop 的无脑重启会反复弹窗打断用户 |
| A1.4 | **退出顺序与孤儿兜底** | 先停 run → 停后端 → 停 kernel。启动时按 bootstate 缺失 `stopped`（即上次异常退出）清理残留的 Python / Node 进程 |
| A1.5 | **网络边界硬约束** | 后端绑 `127.0.0.1` 必须强制，**不提供**任何可改为 `0.0.0.0` 的配置项。本地 agent 的 API 一旦进局域网，等于把文件系统操作能力暴露出去 |

### A2 梯队二 — 决定它是「应用」还是「开发服务」

| # | 项 | 理由 |
|---|---|---|
| A2.1 | **用户数据目录收敛** | 主库、日志库、日志目录、bootstate、workspace 根、设置——现散在 `apps/backend/`。迁到 OS 标准用户数据目录。**这是分水岭**：不补则卸载 = 数据丢失、多版本互相覆盖 |
| A2.2 | **日志可触达 + 轮转保留上限** | 铁律第 6 条要求可排查日志，但桌面用户不知道 `apps/backend/logs/` 在哪（实测仓库根 `logs/` 单日文件已达 3.8 MB 且无上限）。需「打开日志目录」入口 + 轮转/保留策略 |
| A2.3 | **动态端口 + 配置注入** | 不占固定端口，消灭「8000 被占」。前端注入点 `window.__COSIR_RUNTIME_CONFIG__.backendBaseUrl` 已预留 |
| A2.4 | **关窗不退出** | coding agent 的关窗 ≠ 停止任务。一个跑 5 分钟的 run 不该因关窗中断。需托盘 / 后台驻留 |
| A2.5 | **后端未就绪 / 失败时的界面态** | `booting` 期间显示什么、`failed` 显示什么。当前前端只会看到「连不上」，用户无法区分「启动中」与「已崩溃」 |

### A3 梯队三 — 建议补（不紧急，但很值）

| # | 项 | 理由 |
|---|---|---|
| A3.1 | 长 run 完成系统通知 | 用户切走后不用盯着 |
| A3.2 | 首次运行 provider 引导 | `provider_model.py` 注明「不预置内置厂商」，空表触发「无厂商报错」。控制面知道是否首次运行，该给引导 |
| A3.3 | 菜单项：打开日志目录 / 重启后端 / 关于与版本 | 桌面应用基本盘 |
| A3.4 | 数据目录一键打开与清理 | 配合 A2.1 |

### A4 打包期前置问题（严格说不属于控制面，但会决定 A1.2 怎么落地）

| # | 项 | 理由 |
|---|---|---|
| A4.1 | **Python 运行时如何随应用分发**（嵌入式 Python / 打包 uv） | 决定 sidecar 拉起的到底是什么。**建议先定这个再动 A1.2**，否则 sidecar 配置返工 |

### A5 前后端缺口（非控制面，但已核实存在，一并登记）

| # | 项 | 位置 | 理由 |
|---|---|---|---|
| A5.1 | 抽 `CosirConversationTransport` | `components/assistant/assistant-runtime.tsx:41,50` | `prepareSendCommandsRequest` 一个回调塞四件事：WeakMap 分配 commandId、sessionStorage 重试 ID、剥离 state、注入模型选择。业务协议绑死第三方 command 生命周期 |
| A5.2 | `ModelSelectionResolver` | `assistant-runtime.tsx:51` | `readStoredSelection` 结果未归一化直接透传，localStorage 脏值静默发给后端，用户只看到「发送失败」 |
| A5.3 | 错误体前端消费点 | `converter` 只映射 `messages` + `isRunning` | 后端已产出 `{error:{code,message,retryable}}` 但无人消费，用户看不到失败原因 |

| A5.5 | 差异化 ToolUI | `components/assistant/toolkit.tsx` | 16 个工具全部 `render: ToolFallback`。链路已通但展示无差异，是最贴近用户可感知价值的缺口 |

## 第三部分：明确不做

写入即负债，登记以抑制后续提议：

| 项 | 不做的理由 |
|---|---|
| 崩溃后自动续跑 run | LangGraph 中间态（模型调用上下文、工具子进程、挂起审批）无法安全续跑。正确行为是标 `interrupted` 让用户重发。自动续跑最容易造「UI 显示 running 但永远不动」的僵尸态 |
| 自动更新 | 可预留接口，暂不实现 |
| 多窗口 / 多实例 | 与 A1.1 直接冲突 |
| 远程访问 / 多设备同步 | 与 A1.5 直接冲突 |
| 遥测上报 | 本地个人工具，无必要 |
| 客户端工具执行 | 前端职责决议已明确禁止 |
| 事件流协议（`accepted`/`run_started`/`tool_started`…） | 项目已选定 canonical state + revision 快照语义，回到事件流是倒退 |
| command 九态生命周期 | 本地真实触发场景只有两个：双击发送、首帧前断连重试。后端 `conversation_commands` 已覆盖 |
