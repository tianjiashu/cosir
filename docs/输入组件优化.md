> 调研对象：`G:\code\deepseek-harness`（输入框子系统横跨 `packages/client/ui-conversation` 与 `packages/client/ui-input-trigger`）

> 调研方式：5 个并行子 Agent 分维度深度读源码（状态机 / 提交事务 / 触发菜单 / CSS 三层叠合 / 持久化与 a11y），下文每条均标注外部文件行号与本项目对照。

## 一、整体形态（UI/样式）

这是一个浮动胶囊卡片（floating capsule），不是贴底的工具栏：

- **卡片**：`border-radius: 22px` 大圆角，浮动在消息列底部居中（宽度跟随聊天内容列 `--dsh-composer-card-max-width`，缩小时保持左右留白 clearance，不是固定宽）。深色模式用 elevated 表面 + `box-shadow: --dsw-shadow-lv2`。
- **双层结构（mirror + backdrop + textarea 三层叠合）**：这是最精巧处。一个隐藏的 `.mirror` div 撑开完整草稿高度（hero 态最少 2 行），`.backdrop`（透明字形、只透出高亮背景和 ghost hint）和真正的 `<textarea>` 绝对定位叠在它上面，三层共享完全相同的 `font/line-height/padding/wrapping`，所以高亮永远精确对齐字形（注释里详细解释了 WebKit 8px 漂移坑）。
- **textarea 本身**：`color: transparent` + `caret-color: 业务蓝`，文字实际由 backdrop 渲染——这样能在文字上叠加 chip/高亮而不被原生 textarea 限制。
- **自动增高**：`.scroll` 设 `max-height: --dsh-composer-text-max-height` 后 `overflow-y:auto`，草稿超过则卡片内滚动，缩略条用 l2 配色。
- **两种形态同一组件**：hero（空态居中大输入框）和常驻底栏是同一个组件的位置移动，不是两套代码。
- **键盘与交互**：Enter 发送、Shift+Enter 换行（`onKeyDown` 处理），Escape 退出发送态，Alt+Enter 设为编辑态；自动 focus + 严格 caret 管理（`setSelectionRange` + 滚动 reveal）。

## 二、UI / 样式要点（InputBar.tsx + CSS）

- **多行自适应 textarea**：`rows=1` + `resize:none`，用 `useLayoutEffect` 测量 `scrollHeight` 实现 auto-grow（最小 24px，最大 200px 后内部滚动）。
- **状态驱动样式**：`claimed/submitting` 阶段：`opacity-60 pointer-events-none`（冻结输入，防止重复提交）。`disabled`（无会话）：整体灰化。
- **placeholder chip**：当某命令/引用的参数是空时，显示 ghost hint（灰白色斜体提示「接下来输入参数」），叠加在 draft 尾部的 mirror-layer 上。（本项目目前无命令/引用体系，此点仅作形态对照）
- **工具按钮组（tools slot）**：麦克风（语音）、附件。（本项目当前无斜杠命令触发入口）
- **发送/停止双状态**：`frozen/submitting` 显示停止，否则显示发送；发送按钮在 `!canSend` 时禁用。
- **草稿持久化**：`onChange` 写入 chat store（带节流），切换会话/刷新后可恢复。
- **必填校验**：`emptyErrorMessage` 内联展示在底部（如「请输入内容」），而本项目用的是 guard 拦截提示。
- **图片附件**：draft 与 `imageIds` 分离存储，提交时一起发送；发送失败自动 `restoreImages`。

## 三、本项目现状基线（对照用）

- 输入框组件：`apps/desktop/src/components/layout/InputBar.tsx`，受控单行 `<Input>`（`inputValue` 字符串 state），`border-t` 贴底条 + `bg-background`，无卡片/圆角/阴影。
- 发送链路：`handleSend` 内联 `trimmedInput` → `useModelSendGuard.guardSend()` 拦截 → `useTask.createTurn(text)`；成功才 `setInputValue("")`。
- 已具备：IME 防护（`!isComposing`）、上下文占用圆环、多 task 并发流式停止、可排查日志（logInfo/Warn/Error）。
- 缺失：跨 task 草稿持久化、多行 auto-grow、附件、`role="status"` 提示、长按 Enter 防连发、同步提交锁。（**用户已决策：不需要斜杠命令**，故无命令系统）

## 四、维度一：输入状态机与语义解析（纯逻辑层架构）

> 外部核心文件：`ui-conversation/src/client/input/{contract.ts, machine.ts, decorations.ts, facade.ts}`

### 4.1 状态模型（phase）
外部 `contract.ts:215` 定义 `phase: 'plain' | 'adjudicating' | 'claimed' | 'submitting'`。`adjudicating/submitting` 由 `facade.ts:52-58` 的 `guardOf` 折叠为 `'frozen'`（UI 锁定别名）。所有草稿/引用变更在非 `plain/claimed` 阶段被机器结构性拒绝（`machine.ts:265,280,312`）。
**本项目**：无显式 phase，用 `streamingTurnId`/`operation.loading` 近似「提交在飞」，但流式期间输入框文本仍可被编辑（仅按钮 disabled），缺少结构性互斥。

### 4.2 草稿数据模型
外部 draft 是**纯文本字符串**，语义实体（命令/引用）用 `U+FFFC` 占位符 + 独立 `Occurrence` 表（`machine.ts:24`，`contract.ts:158-173`）承载，渲染与序列化各自投影；`invalid` 是 style bit 不是删除（`machine.ts:344-354`）。
**本项目**：`inputValue` 纯裸字符串，暂无引用/附件（用户已决策不做斜杠命令，故无命令语义）。该解耦模型对「未来 `@文件引用`」有储备价值，但当前 YAGNI。

### 4.3 装饰推导（纯函数）
`decorations.ts:90 deriveDecorations(state, lexicon)` 是零 React 纯函数，从 `InputState` 推导 `chips/token/textRefs/hint`（`decorations.ts:40-49`）。机器不写 queue，queue 由 facade 层 overlay。
**本项目**：无「状态→派生渲染」中间层，`placeholder` 内联在组件。

### 4.4 contract.ts 接口边界亮点
- 三层可见性隔离（业务包只见 `InputState`，`InputMachine` package-private 不导出）。
- 单一写路径 `dispatch(event)`（`machine.ts:151`）+ `InputEffect` 副作用外置（`contract.ts:286`）。
- `SnapshotStore<InputState>` 不可变快照发布（`contract.ts:58`），UI 订阅渲染。
- `InputNotice` 独立通道（`contract.ts:86-91`，带 `seq` 去重），与 draft/phase 解耦。
- 时钟注入（`contract.ts:201-206`），机器零 ambient 依赖，可纯单测。

## 五、维度二：提交事务与失败恢复

> 外部核心文件：`ui-conversation/src/client/input/{facade.ts, hub.ts, machine.ts}`

### 5.1 submit 事务流程
`machine.onEnter`（`machine.ts:460-477`）：`claimed`→`submitting`；`/前缀`→`adjudicating`（产 `adjudicate` effect）；否则→`default-sink`。每步失败均显式回滚且**不丢失草稿**；`adjudication-failed` 仅 `phase→plain` + notice error（`machine.ts:501-507`），绝不静默降级。

### 5.2 乐观提交 + 失败恢复
外部先 `commitSend` 乐观清空（`hub.ts:149-168`），`sendSession().catch` 中 `restoreImages` + 仅当 `draft===''` 才 `setDraft(text)` 恢复（防覆盖并发输入）。
**本项目**：「成功才清空」更安全，但缺 `restoreImages` 对应物；未来加图片时对齐「清空即 commit，禁止 undo 复活」（`facade.ts:155-159`）。

### 5.3 队列（queue）叠加 + 加速 Enter steer（FIFO）
外部把 session 的 `queued messages` overlay 到 `InputState.queue`（`facade.ts:496-499`）；空 draft + `Ctrl/Cmd+Enter` 一次性把队列按 FIFO steer 进运行中的 turn（`InputBar.tsx:325-334`，`hub.ts:182-192`）。
**对本项目价值**：完美契合「同 task 内 turn 串行」——队列即串行待执行队列。需在 turnStore 增 `pendingQueueByTaskId`。

### 5.4 防重复提交
外部「enter 即切 phase」同步锁（`machine.ts:461` 早返回），无异步缝隙；`readOnly` 而非 `disabled` 保留草稿可见（`InputBar.tsx:704`）；`if (e.repeat) return` 防机关枪（`InputBar.tsx:323`）。
**本项目**：`canSend` 依赖异步 `operation.loading`，存在连点双提交竞态窗口。

### 5.5 可借鉴点
| 名称 | 外部文件行号 | 本项目现状 | 建议落地 | 优先级 |
|---|---|---|---|---|
| 同步提交锁（enter 即锁，无异步缝隙） | `machine.ts:461`、`facade.ts:198-209` | `canSend` 异步竞态 | 加 `submittingRef`（`useRef<bool>`），`handleSend` 顶部 `if(submittingRef.current) return`，`finally` 复位 | **P1** |

## 六、维度三：斜杠命令与触发菜单（用户决策：不做）

> 外部核心文件：`ui-input-trigger/src/client/{MenuView.tsx, controller.ts, core/detect.ts, core/menu.ts, types.ts}`
> **决策结论**：用户明确「不需要斜杠命令」。本维度仅保留调研事实作为对照记录，**整体移出可借鉴清单**，不在本项目实现命令系统。

### 6.1 外部实现概览（对照参考，非借鉴）
- 菜单 UI：`role="listbox"` + `aria-activedescendant` combobox（`MenuView.tsx:100-103`）；分组+图标+描述；外部点击仅 composer card 外才关（`MenuView.tsx:54-65`）；`MAX_HEIGHT=320` 夹紧（`MenuView.tsx:22-43`）。
- 触发检测：`detectTrigger` 从 caret 左扫（`core/detect.ts:47-63`），排除 `//`、`scheme:`；guard tier 按 phase 启用。
- 命令 token：`PickOutcome`（`types.ts:90-95`）含 `claim`/`insert`/`text`；claim 后用 `draft.startsWith(token)` watch 保活（`machine.ts:212-217`）。
- adjudicate：提交时 `startsWith('/')` 先解析、未命中回落 `default-sink`（`machine.ts:471-476`）；bail 事件 + `draftRev` 乐观锁（`machine.ts:259-262`）。

### 6.2 为何本项目不做
1. **当前是纯文本单行输入框**，无命令/引用语义需求，命令 token 全套状态机（`CommandClaim`/`U+FFFC`/`Occurrence`/`codec`）属重型架构，引入即过度设计（YAGNI）。
2. 用户已拍板，故本维度不进入 P0/P1/P2 任何落地项，也不预留命令解析钩子。
3. 若未来确需命令系统（如 `/file@path` 引用），届时单独立项，仍可参考本维度的 combobox 模式与 adjudicate 回落思想，但那是独立决策，不在此次优化范围。

## 七、维度四：CSS 视觉细节与三层叠合渲染

> 外部核心文件：`ui-conversation/src/client/skeleton/InputBar.module.css`、`InputBar.tsx`、`ui-theme/src/styles/{design-platform.css, scrollbar.css, gradient-shadow-text.css}`

### 7.1 三层叠合架构
`.scroll`（唯一滚动盒）→ `.grow`（position:relative）→ `.mirror`（普通流撑高，visibility:hidden）+ `.backdrop`（absolute inset:0，渲染高亮）+ `.textarea`（absolute inset:0，`color:transparent`）。三层共享同一组 `box-sizing/padding/font/line-height/white-space`（`InputBar.module.css:221-254`）。
**WebKit 8px 漂移坑**：`.scroll` 出现滚动条时三者的宽度被同步收窄（`.input` 自身 `overflow:hidden` 绝不自滚），否则 backdrop/mirror 比 textarea 窄 8px 导致换行错位。

### 7.2 textarea 透明字 + caret 着色
`.input { color:transparent; caret-color:业务蓝 }`，真实文字由 backdrop 的 `<mark>`/`<span>` chip 渲染——解决原生 textarea 无法对局部字符做彩色高亮/chip/ghost hint 的限制。

### 7.3 浮动胶囊 + clearance 对齐
`.card { border-radius:22px; box-shadow:lv2; max-width:calc(748+32) }`；`--dsh-composer-side-clearance:16px` 让输入框与内容列严格对齐（`ConversationRoot.module.css:22-25`）。深色用 elevated 表面（比 body 更亮一档）。

### 7.4 自动增高与滚动条 token
增高靠 `.mirror` 撑高而非 JS 设高；`.scroll` 仅设 `max-height`。`scrollbar.css` 用 `--dsh-scrollbar-thumb` 变量 indirection + `@supports not selector(::-webkit-scrollbar)` 双路径分流（Firefox `scrollbar-width:thin` / WebKit `::-webkit-scrollbar*`），hover 在两条路径都生效。

### 7.5 design token 双层命名
`--dsw-*`（语义别名层：bg/border/label/state/scrollbar）+ `--dsh-*`（宿主布局层：max-width/clearance/max-height）；明暗在 `body[data-ds-dark-theme]` 整体重定义 alias，组件零改动；阴影层级 `--dsw-shadow-lv1/2/3`。

### 7.6 可借鉴点
| 名称 | 外部文件行号 | 本项目现状 | 建议落地 | 优先级 |
|---|---|---|---|---|
| 输入框左右 clearance 显式 token 化并对齐内容列 | `ConversationRoot.module.css:22-25` | 固定 `px-4` | 改 `mx-auto max-w-content px-(clearance)` | **高** |
| 滚动条 token indirection + `@supports` 双路径分流 | `scrollbar.css:17-90` | `.scrollbar-thin` 未分流、hover 失效 | 定义 `--scrollbar-thumb/width` 变量 + `@supports` 分流 | **高** |

## 八、维度五：草稿持久化、附件、IME、键盘、无障碍

### 8.4 键盘交互矩阵

## 九、落地优先级总览（立即可做 → 远期）

### P0（低成本高收益，建议立即落地）
1. **跨 task 草稿缓存**：`useTaskStore` 增 `drafts` map + mount 回灌（解决切换/刷新丢草稿）。
2. **长按 Enter 防连发**：`if (e.repeat) return`（一行代码）。
3. **a11y 补齐**：`<Input aria-label>` + 拦截提示 `role="status" aria-live`。
4. **同步提交锁**：`submittingRef` 防连点双提交竞态。

### P1（架构/体验增强）
5. **`canSend`/`canStop` 纯函数化 + 副作用外置**：抽 `useInputState` / `useSendInput` hook，让 `InputBar.tsx` 变薄可测。
6. **输入框左右 clearance token 化 + 滚动条 `@supports` 双路径分流**（修复现有 hover 失效）。
7. **自动 focus + keepFocus**（避免点按钮丢焦点、切换 task 需手动点）。
8. **IME 三路判定 + composingRef 延迟清位**。

### P2（功能/严谨性打磨）
9. **队列叠加 + 空 draft 加速 Ctrl/Cmd+Enter 批量提交**（契合多 task 并发、同 task 串行，不依赖斜杠命令）。
10. **统一 notice 快照通道**（level/seq/role=status）。
11. **草稿镜像写回节流**、**发送失败 restore 草稿+附件**（图片上线时）。

### 风格/体系化（需先过设计原则决策）
12. **浮动胶囊卡片**（圆角 16-22px + lv2 阴影 + 深色 elevated）——与本项目「无阴影」原则冲突，需 ui-guidelines 拍板。

### 明确不照搬（YAGNI / 已决策不做）
- **斜杠命令全套**（`CommandClaim` / `U+FFFC` 占位符 / `Occurrence` / `codec.serialize` / bail 事件总线 / per-session controller / Span CAS 乐观锁）：用户已明确决策不做斜杠命令，本维度整体移出借鉴清单（见第六章）。
- 上述命令 token 架构是为「命令 + 引用 chip」设计的重型机制，本项目当前是纯文本单行输入框，仅抽取其「单一写路径 + publish 镜像 + per-session store 持久化」的骨架思想即可，不引入复杂度。

## 十、核心结论

deepseek-harness 的输入框把「**状态（machine）+ 派生（decorations）+ 副作用执行（facade）+ 契约边界（contract）+ 持久化（store）**」彻底分层，机器零 React/零 DOM/零时钟、可纯单测；UI 仅是「喂事件 + 读快照渲染」。

本项目 `InputBar.tsx` 当前把守卫/loading/校验/拦截/日志/perf 全部内联在组件，**最值得立刻借鉴的是 P0 四条（草稿缓存、防连发、a11y、同步锁）+ P1 的 `canSend` 纯函数化与副作用外置**——改动小、能立刻让组件变薄可测，并为未来富输入（附件/引用高亮）预留干净的数据模型。斜杠命令已明确不做。
