# 客户端间距与自适应审查报告

- **审查对象**：`apps/desktop` 前端客户端（React 18 + TypeScript + Tailwind CSS 3 + shadcn/ui 风格组件）
- **审查日期**：2026-08-05
- **审查方式**：全量静态代码审查（覆盖 `src/` 下全部 40+ 组件与样式配置文件），并经子 Agent 独立复核源码行号与论断
- **审查维度**：间距一致性与「自适应间距」（responsive/adaptive spacing）能力
- **状态**：v1.2（终稿，已通过子 Agent 两轮审查）

---

## 1. 总体结论

间距体系处于「**有共识、无令牌**」状态：Tailwind 原子类使用总体克制、8px 步进的高度体系一致，但存在 **2 处确定性溢出风险** 与 **6 处一致性 / 自适应缺口**。

布局级自适应已经具备：三栏结构由 `react-resizable-panels` 管理，支持拖拽调宽、最小宽度保护（侧栏 180px / 右栏 200px / 中央 320px）、并按视图维度持久化到 localStorage。**内容级自适应几乎缺失**：全源码仅有 3 处 `sm:`/`md:` 响应式断点（`TopBar.tsx:83,92`、`NewTaskPage.tsx:159`），无 `lg:`/`xl:`、无容器查询、无基于面板宽度的自适应机制。

**一句话结论**：溢出类问题（2 处）应优先修复；一致性问题（6 处）建议通过设计令牌收敛；内容级自适应属于结构性缺口，建议以容器查询分阶段补齐。

## 2. 问题清单

### 2.1 确定性溢出风险（P0，需优先修复）

| # | 位置（文件:行） | 问题描述 | 触发条件 |
|---|---|---|---|
| 1 | `src/components/right-panel/ChangesToolbar.tsx:42-46` | 外层 `flex justify-between` 内按钮组 `flex gap-1` 不换行，「已选 N 项」+ 3 个按钮横向排布 | 右栏拖至 200px 最窄时横向溢出 |
| 2 | `src/pages/logs/LogsPage.tsx:143-173` | 头部工具栏三控件（trace 输入框 `w-72`、级别 select、查询/刷新按钮）同处不换行 flex 容器 | 中央面板拖至 320px 最窄时，按 min-content 估算（输入框≈164px + select≈70px + 按钮≈80px + gap≈16px ≈ 330px）超过可用宽度约 288px，横向溢出 |

### 2.2 一致性与自适应缺口（P1）

3. **InputBar 内嵌按钮与输入框重叠是常态，非条件触发**（`src/components/layout/InputBar.tsx:134,138`）：输入框 `pr-24`（96px 预留）与内嵌按钮组 `absolute right-1.5` 是手工耦合的魔法值对。实测 `AgentSelector.tsx:76` 标签带 `max-w-[80px] truncate`，按钮组宽度有界（Agent 选择器约 110px + 麦克风按钮 ≈ 140px），**已超过 `pr-24` 预留的 96px**——即输入文本与右侧按钮重叠是常态，而非「Agent 名称变长」才触发；且宽度对齐完全依赖两处魔法值手工同步，无结构性解耦。
4. **侧栏区块间距基准混用且左缘不对齐**（`src/components/layout/Sidebar.tsx:177,187,199,210`）：同一滚动区内，「应用标题」用 `px-4`（16px）、「新建任务」用 `p-2`（8px）、「日志」用 `px-2 pb-2`、「工作区」用 `px-2 py-1`——标题区与内容区左缘差 8px，三内容区块垂直节奏参差；`HistoryList`/`PluginList`（`px-2 py-1`）与主区块间亦无统一区块间距规则。
5. **会话列宽不可伸缩**（`ChatPanel.tsx:136`、`TurnTimeline.tsx:60,67`、`InputBar.tsx:112`、`NewTaskPage.tsx:152`）：`max-w-3xl`（768px）共 5 处硬编码重复。行为不对称——面板拖窄时内容收缩，拖宽超过 768px 后内容不再伸展，阅读宽度上限固定而非区间自适应。
6. **层级间距不分**（`ChatPanel.tsx:136` 与 `TurnTimeline.tsx:59` 均为 `space-y-4`）：turn（轮次）之间与 turn 内部条目之间同为 16px，多轮对话时 turn 边界视觉粘连，层级没有区分。
7. **消息气泡宽度与列宽 token 脱节**（`AgentMessage.tsx:208`、`UserMessage.tsx:37`）：`max-w-[85%]` 在两处独立维护，与 `max-w-3xl` 列宽体系无联动，且 85% 固定比例在窄面板下会产生过窄观感。
8. **右栏 Tab 栏与内容区左右不对齐**（`RightPanel.tsx:87` vs `:107`）：Tab 栏 `mx-2`（8px），内容区 `p-3`（12px），左右基准不一致，Tab 按钮左缘与内容左缘相差 4px。

### 2.3 其他散乱现象（P2）

- **魔法字号**：`text-[11px]`/`text-[10px]` 散落 7 个文件共 30 处（`BackendErrorBanner`、`AgentSelector`、`StatusBadge`、`TerminalCallCard`、`ToolCallCard`、`ConversationTraceBlock`、`WorkspaceIndexBadge`），未纳入 `messageTypography` 令牌体系（该文件仅收敛了 13px/12px 两档正文）。注：`ChangeFileRow` 使用标准 `text-xs`，不属此类。
- **缩进刻度不统一**：侧栏子任务缩进 `ml-5`（`Sidebar.tsx:253`）与工具卡展开详情缩进 `ml-6 pl-3`（`ToolCallCard.tsx:296`）为手工对齐，无统一缩进刻度。

## 3. 自适应（responsive / adaptive）能力评估

| 层级 | 现状 | 评估 |
|---|---|---|
| 布局级自适应 | 三栏可拖拽（`react-resizable-panels`）、最小宽度保护、布局持久化（`App.tsx:48-49` 按视图分离存储） | ✅ 已具备 |
| 尺寸常量管理 | 面板默认/最小宽度集中声明于 `App.tsx:67-78`，尺寸基准（默认窗口 1200×800、最小 960×640）注释于 `App.tsx:89-91` | ✅ 良好 |
| 内容级自适应 | 仅 3 处断点：`TopBar.tsx:83`（`md:inline` 隐藏模型信息）、`TopBar.tsx:92`（`sm:flex` 隐藏环境信息）、`NewTaskPage.tsx:159`（`sm:grid-cols-2` 快捷卡片） | ⚠️ 近乎缺失 |
| 面板宽度驱动的自适应 | 无容器查询（`@container`）、无基于面板宽度的布局切换 | ❌ 缺失 |

**关键缺口**：桌面端窗口可 resize，三栏宽度可拖拽变化，但内容布局完全静态——中央列宽固定上限、右栏工具按钮不换行、日志输入框固定宽度，均未响应所在面板的实际宽度。

## 4. 值得保留的正例

- **面板尺寸常量集中声明**（`App.tsx:67-78`）：默认/最小宽度有注释、有最小宽度保护，是布局常量的良好实践。
- **排版令牌雏形**（`src/components/chat/messageTypography.ts`）：收敛了正文/次要/代码三档字体与行高，注释说明设计意图。
- **自适应换行范式**（`BackendErrorBanner.tsx:73`）：错误横幅操作区使用 `flex flex-wrap items-center gap-2`，窄宽度下自动换行，是内容级自适应的正确写法，可推广到其他工具条。
- **消息列表性能分层**（`TurnTimeline.tsx`）：按 turn 独立投影 + memo，间距结构（`space-y-4`）与性能解耦，未把间距写死在业务逻辑里。

## 5. 修复建议（按优先级）

### 5.1 必须（P0 溢出修复）

1. **ChangesToolbar 换行**：按钮组外层容器加 `flex-wrap`（对齐 `BackendErrorBanner` 的既有范式），或右栏窄时按钮图标化。涉及文件：`src/components/right-panel/ChangesToolbar.tsx`。
2. **LogsPage 头部自适应**：trace 输入框 `w-72` 改为弹性宽度（如 `w-48 min-w-0 flex-1` 或限制 `max-w-*`），使头部三控件在 320px 中央区内不溢出；必要时头部整体加 `flex-wrap` 兜底。涉及文件：`src/pages/logs/LogsPage.tsx`。

### 5.2 建议（P1 令牌化）

3. **InputBar 内嵌按钮解耦**：将 `pr-24` + `absolute right-1.5` 的魔法值对改为 flex 布局（输入框与内嵌按钮组同处一个 flex 容器，按钮组占位自然参与宽度计算），消除手工对齐耦合与预留不足。涉及文件：`src/components/layout/InputBar.tsx`。
4. **列宽令牌化**：在 `tailwind.config.ts` 的 `theme.extend.maxWidth` 定义 `content: "48rem"`（768px）等具名令牌，替换 5 处 `max-w-3xl` 硬编码（`ChatPanel.tsx:136`、`TurnTimeline.tsx:60,67`、`InputBar.tsx:112`、`NewTaskPage.tsx:152`），使列宽可单点调整。
5. **层级间距分层**：需同时改动两处——turn 之间 `space-y-4` → `space-y-6`（`ChatPanel.tsx:136`），turn 内部条目之间 `space-y-4` → `space-y-3`（`TurnTimeline.tsx:59`），用间距差建立视觉层级。
6. **气泡宽度纳入令牌**：`max-w-[85%]` 提取为统一 token（如 `bubble-max-w`），并与列宽联动（气泡宽 = 列宽 - 固定边距），消除 `AgentMessage.tsx:208` 与 `UserMessage.tsx:37` 两处独立维护。
7. **统一面板基准间距**：侧栏（`Sidebar.tsx:187,199,210`）与右栏（`RightPanel.tsx:107`）内容 padding 收敛为同一令牌；右栏 Tab 栏（`:87`）与内容区左右对齐。侧栏标题区（`:177`）与内容区左缘统一为同一基准。
8. **魔法字号收敛**：`text-[11px]`/`text-[10px]` 收进令牌体系（如 `messageTypography` 增加 `caption: "text-[11px] leading-4"`），替换工具卡片、右栏与侧栏中的裸写。**注意**：`messageTypography` 位于 chat 层，而魔法字号大量出现在右栏/侧栏/backend 组件，令牌归属需全局化（建议放入 `src/index.css` 或独立 tokens 文件），避免跨层引用。

### 5.3 以后（P2 结构性改进）

9. **容器查询**：对中央列宽容器启用 `@container`，实现「列宽随面板拖拽连续伸缩、气泡按容器比例伸缩」的真自适应；这是内容级自适应的根本解法。
10. **侧栏折叠模式**：侧栏支持折叠为图标模式（参考成熟桌面 IDE），最小宽度进一步下探。

### 6.2 间距模式统计（抽样）

- `gap-*` 出现于 30 个文件，`gap-2`（8px）为最常用值，次为 `gap-1`/`gap-1.5`/`gap-3`——间距梯度本身一致。

- 响应式断点：全源码 3 处（见 §3）。

### 6.3 术语说明

- **布局级自适应**：窗口/面板尺寸变化时，布局结构（栏宽、显隐）随之调整。
- **内容级自适应**：布局结构不变时，内容宽度、间距、控件排布随容器宽度调整。
- **间距令牌（spacing token）**：将间距值抽象为具名变量/设计系统常量，替代散落的魔法值，保证全站一致并支持统一调整。
