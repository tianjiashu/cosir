# 文件引用与链接意图改造

## 已确认的目标与归属

2026-11-06：用户确认实施，不提交 Git。文件地址与文件名查找必须是不同意图；不从根目录存在性、搜索排序或当前预览猜测模型指向。保留识别 → 解析 → 打开的分层，磁盘事实与访问校验仍由后端文件服务负责。无需新数据库、索引、消息字段或唯一文件名解析 API。

调查证据：`lib/links/resolve-link.ts` 的 `mention` 把未知位置编码成根路径；`use-open-workspace-path.ts` 的 `ifMissing` 再转搜索；`markdown-links.tsx` 却统一提示打开文件。文档行内代码遗漏 documentDir；搜索请求未携带行号；终端为 URL 解析自行转义原始路径；引用解析支持四种协议而 Markdown sanitize 只允许两种。

## 行为契约

- 明确 Markdown 地址（包括只有 basename 的 href）是地址，按来源基准打开，不自动搜索或换文件。缺失时提示，用户可主动查找同名文件。
- 行内代码中有目录的路径是字面路径，按当前文档目录（文档预览）或工作区根（消息）换算。裸文件名只提供独立的查找按钮，正文保持代码样式；悬停/聚焦显示小型搜索入口，有明确 accessible name，不伪装成文件链接。不先尝试根目录，也不自动选择唯一结果。
- URL href 解码一次；原始文件路径不 URL 解码，百分号与井号按字面保留。终端只识别工作区内绝对路径，不猜 shell cwd。
- 文件名搜索复用现有列表、分页、取消和错误状态。引用发起的查找显示“选择文件以打开”；候选确认后携带原行号交给统一文件打开入口。修改查询、清空、选择完成时清除导航意图。
- 现有已打开文件不会被发起搜索替换；只能用户选择候选后改变。
- 自定义引用协议白名单与 codec 支持一致。用户引用片段展示消息快照；模型回答中的地址打开当前文件，不从地址凭空构造快照。
- 已知路径的模型输出使用 `[API.md](docs/brand/API.md)`，短显示名不能缩短目标。未知路径不猜测；需要链接时先查证。共用 output_layer，不分别维护主/子 Agent、Team 提示词。
- 已有 Task 固定提示词不改写；新提示词对新 Task 生效。前端确定性处理同时适用于历史消息。
- 异步打开需验证连续点击、工作区切换与关闭面板的迟到响应，必要的收敛只放在导航边界。日志继续经 frontendLog 落盘，区分搜索与打开结果。

## 范围与刻意不做

修改统一链接解析/打开、Markdown 识别、搜索导航、提示词、相关测试。保持工具结构化路径、输入引用 codec/快照、配置 webOnly、本机/外部网页规则、文件服务访问边界。

不改历史消息与系统提示词持久化；不做自动唯一匹配、新索引、默认排除 node_modules、搜索排序、跨文档标题锚点或大文件绝对行号定位。大文件保持现有“无法定位”说明。

## 验收要求

单测覆盖显式地址/查找意图区分、根文件存在仍不抢开、文档相对路径、原始与 URL 编码路径、行号和四种引用协议的完整 Markdown 渲染。真实 Python 文件服务 + Chromium 覆盖三个同名文件（根目录、业务目录、node_modules）、选择后定位、缺失提示、特殊字符、查询编辑/取消、快照和导航生命周期。既有文件/引用/终端测试回归；类型检查与定向 lint。完成后 gpt-6-sol 基于本文独立只读复核。
