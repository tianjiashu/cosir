# 内置浏览器环境与执行契约改造方案

日期：2026-11-08。状态：方案待确认，未实施业务代码变更。

目标是在现有 Electron 内嵌体验中，减少客户端环境差异、错误操作、取消失效和不准确回执造成的额外网站风控风险。保留 `WebContentsView`、宿主 CDP、持久登录分区、Task 标签归属和现有用户交接。采用局部结构重构：默认值回到真正覆盖所有网页的来源，操作生命周期由一个执行者负责，执行事实与页面观察分别表达，交接约束复用既有登记表。

本次不建设指纹配置平台、多 Profile、代理轮换、通用任务队列或自动重试系统。网站是否放行仍取决于账号、网络和站点策略；以下验收证明实现行为正确，不以未知站点的风控通过率替代工程验收。

## 已确认的需求和行为边界

- 保留当前内嵌面板和用户直接操作网页的能力。
- 继续共用 `persist:cosir-browser`，不清除 Cookie、站点存储或登录状态，不按 Task 自动分区。
- Agent 的动作可停止，停止后不继续发送后续业务输入；已经发送的输入不能承诺撤销。
- 页面观察失败不抹掉已经获得的执行回执。输入序列完成不等于网站业务提交成功。
- 明确交接的标签受 Agent 操作约束；用户关闭、导航和回答弹窗仍有控制权。
- 手机视口属于布局测试能力，不升级为手机设备身份伪装。

## 路线比较与选定终态

逐点补丁路线是在 popup 再设 UA、每个输入循环加取消判断、各调用方捕获快照异常，再给浏览器补一个队列。它会把同一不变量分散到多处；逐标签补 UA 已经有失败反例。排除这条路线。

选定局部结构重构：保留当前职责合理的模块，在四个实际边界替换旧路径。只新增有当前生产职责的具体实现，不引入单实现 Protocol、插件接口或备用执行引擎。

| 所有者 | 唯一负责的事实 | 改造后仍不负责 |
| --- | --- | --- |
| 宿主启动装配与 Session 配置 | 默认 UA、应用缓存、网站持久分区和权限 | Task 调度、账号身份模型 |
| BrowserHost | 标签归属、实际目标解析、操作路由与状态投影 | 第二份操作状态、持久交接表 |
| BrowserTab | 唯一持有当前操作、标签生命周期与页面代次 | 网站业务是否成功 |
| 具体 BrowserOperation | 本次信号、在途命令、输入单元进度与收尾 | 排队任务、自动重试、跨重启恢复 |
| 输入动作模块 | 点击、输入、选择等动作语义 | 独立时限、自己的重试与后台任务 |
| 后端 handoff_registry | 哪个资源明确交给了用户 | 宿主标签是否还活着 |
| wire、后端呈现与 React | 同一执行回执和观察结果的表达 | 重新推断动作是否成功 |

## 默认环境与缓存

UA 在任何 WebContents 创建前从当前 Electron 的实际默认值计算一次，设入 `app.userAgentFallback`。删除 `configureBrowserSession` 中的独立 `setUserAgent`，保留 Session 的权限和下载装配。应用自身渲染页也使用这一默认 UA，这是有意变化；不在 Session 和 Tab 层再保存第二份可变 UA。

移除 `disableHttpCacheForDevServer` 的进程级开关及启动调用。推荐开发界面固定使用 `persist:cosir-ui-dev`，首次创建时设置 `cache: false`；窗口创建和权限处理必须引用同一个 Session。打包应用继续使用现有应用 Session。按绿地项目约定不建设存储迁移层：开发界面原本存在默认 Session 中的本地偏好会一次性重置，之后继续持久保存，这是需确认的有意行为变化。网站 `persist:cosir-browser` 保持原位置，不迁移、不清理。新策略必须通过修改 Vite 依赖后重启和重新加载的回归，避免重新引入原缓存故障。

保留 `TabEmulation` 的视口、缩放、颜色与手机布局职责。设备预览不是账号身份；不为统一 UA 顺带增加语言、时区、字体、Canvas 等覆盖。

## 操作生命周期与取消语义

在现有 `BrowserHost.operate` 与 `BrowserTab.pageSession` 边界引入具体 `BrowserOperation`，由标签持有当前修改操作。输入模块使用该执行上下文；旧的未绑定 signal 的散装能力传递被替换，不保留一条原始 CDP 旁路用于普通动作。`CdpSession` 继续负责协议、页面暂停和单命令等待，操作对象负责这次业务调用的生命期，两者不互相重复拥有同一状态。

同一标签的 Agent 修改请求在已有操作未收尾时立即返回忙，不排队执行过时意图。范围包含 act、navigate、evaluate；任意 evaluate 按可能修改处理，不通过解析脚本猜测它是否只读。日志、标签列表和必要的状态核对可读。close、用户回答弹窗属于控制路径，不能被普通操作占用挡住。Agent 现有 `browser.act` 仅在整批只有一个带显式 id 的 dialog 动作时进入同一答复控制路径；带其他动作的混合批次不能借此绕过占用。交接检查仍然生效，不增设另一套弹窗工具。

按实际副作用区分读取与修改，不按工具名称猜测：`browser-tab.ts:423-428` 的元素截图经 `input/element.ts:52-54` 滚动目标，并经 `page-frames.ts:61-76` 滚动祖先框架。因此带 ref 的截图也进入修改操作边界和交接检查；普通快照、日志与不滚动的截图保留观察语义，不为此重写截图实现。

取消分成两个边界：

1. 尚未开始的输入单元不再派发。逐键输入中的下一字符、最后的 submit 回车都是后续单元。
2. 已发出的单元可能已生效。按下与释放需要明确成对语义；外层取消可以结束等待，但不把底层在途命令当成已终止。

执行上下文在命令发出边界检查信号，持续跟踪底层 Promise 的落定。现有 `CdpSession.send` 将底层 Promise 包在可提前 reject 的等待中，调用方无法观察实际完成；阶段二须同步调整其内部命令完成契约，让操作对象得到真实落定通知，不能仅给旧包装传 signal。命令确认落定、必要收尾完成后才允许新的 Agent 修改。

收尾规则必须验证后固化：

- 确认在同一页面代次且输入状态已知时，按当前输入单元语义完成释放；这可能完成一次 click，回执必须如实表达。
- 页面已导航、用户已介入或按下是否生效未知时，不盲目补发 keyUp 或 mouseReleased 到新页面。
- 浏览器进程侧的拖放拦截撤销沿用现有独立清理通道，不受已取消的业务信号阻断。
- 弹窗暂停时保留必要在途状态，用户回答和单独的 dialog 控制动作仍可执行，避免等待清理与等待答复互相卡住。旧批次因取消结束后不得恢复其后续业务动作。
- 收尾等待有界；到时仍无法确认的，当前操作进入隔离态，阻止新的 Agent 修改。若仍在预留回复时限内，返回未知回执；总时限到达或客户端已取消时，当前调用可能只有超时或没有答复，未知状态须能在后续状态读取中看到。用户可关闭重开标签恢复。不自动重放、不自动刷新、不为了清理偷偷继续提交。

这里允许保留的是“尚未收敛的当前操作”，不是再增加一个独立 busy 标志或恢复状态库。底层命令可能永不落定，隔离态可持续到标签关闭；请求结束不等于操作已收敛。界面从操作状态区分执行中与需要关闭重开的未知状态，不让忙碌动画无限转动。弹窗答复和关闭仍可用。未知输入状态的隔离仅作用于该标签，不能阻止其他 Task 正常工作。

用户 IPC 导航先请求停止旧 Agent 操作，确认收敛后执行导航；若输入状态未知，拒绝复用该标签导航并明确提示关闭重开，不自动换页或暗中重建标签。用户关闭可直接终止标签生命周期。真实网页内的人工输入不能被软件层保证回滚，明确交接是本次保证的人机边界。硬件事件归因尚未可靠验证时，不承诺任意同时操作都能自动识别。

## 执行回执与页面观察

删除 `ActOutcome = PageResult & ActResult` 的强制绑定，替换为一个动作响应中的两个独立部分。以下是契约语义，实施时由一份领域结果定义和既有 wire 样例表达，前后端不各自发明字段。

| 部分 | 语义 |
| --- | --- |
| execution | 每步目标与结果：完成、未开始、被中断；中断时说明尚未派发，还是可能已有部分作用 |
| observation | 当前页面结果，或无法取得页面的原因；页面关闭也是一种观察结局 |

目标说明在动作执行前取得，避免导航清空 ref 后再回查。步骤列表是唯一执行事实；旧 `completed/failure/targets` 组合在调用方全部迁移后删除，不长期并存两种结算方式。

`runActions` 负责动作结算，页面加载等待和事后快照归观察阶段。保留必要的逐步等待：每一步先记录执行事实，再等待页面达到下一步可操作条件，不把所有等待移到整批末尾。观察失败可停止后续批次推进，但不能反写前一步为“没有执行”。`DialogOpenedByAction` 也不能继续一律等于整个动作完成：按下阶段弹窗和释放后弹窗要按实际阶段结算。

BrowserHost 在执行完成后即持有独立回执。后续标签关闭、快照失败或解析失败，仍在链路可回复时返回该回执；不能由通用 `assertOpen` 再把已知结果覆盖成只剩 TAB_NOT_FOUND。输入完成只描述工具操作，不据此宣称订单、登录或发布成功。

同步替换 `wire.ts`、`contract/wire-samples.json`、后端 `act.py`、`rendering.py`、`browser_display.py` 和前端步骤展示。新增“结果不确定”表达，不能为了沿用 done/failed/skipped 强行归为 failed。

结果读取与增量基准提交分开。宿主决定回复且请求尚未取消、页面代次仍匹配时，才在一处提交 `deliver` 和 `TabLog.digest`；输入、wire、UI 不各加判断。这只保证宿主提交条件，发送前后仍可能遇到取消或断连，不能保证模型收到。`withinDeadline` 保留总时限，host-link 保留取消后丢弃结果的语义，不引入 ack 协议；后续请求先读完整状态恢复观察基准，丢弃旧增量假设。

## 交接与用户控制

交接仍以 `handoff_registry` 为唯一事实源。后端浏览器请求入口读取本 Task 的交接标签，作为本次请求的内部约束传给宿主；该字段不成为模型参数、不在宿主持久化、不通过前端维护镜像。

宿主先解析实际目标标签，再在修改入口检查该请求约束，之后才开始异步操作。这样不需要后端为了省略 tab 的调用额外查询 current，再与宿主重复维护目标事实。

| 操作 | 交接中的处理 |
| --- | --- |
| Agent act、navigate 当前页、evaluate、close | 拒绝修改交接目标，说明需用户交还 |
| Agent 带 ref 的元素截图 | 因定位会滚动页面，按修改检查；可改读普通截图 |
| Agent snapshot、logs、标签列表 | 允许观察，不自动解除交接 |
| Agent select 标签 | 可切换当前目标，之后的修改仍检查实际目标 |
| Agent 新开其他标签 | 保持现有行为，不把单标签交接升级为全 Task 锁 |
| 用户导航、关闭、回答弹窗、交还 | 保留控制权；导航与关闭按操作生命周期规则抢占 |

这是请求发起时点的约束，不能称为跨进程强一致锁。当前同 Task 浏览器工具串行、交接工具不能与其他决定动作混批，限定了常规竞争路径；begin/end/drop、宿主断连和标签自关闭仍需测试。关闭后交接如何结束继续沿用现有交还与资源不存在语义，不为本次引入宿主主动上报后端的新通道。

同一持久 Session 内的网站脚本、登录 Cookie 和跨标签账号状态仍可能相互影响。单标签交接约束的是 Agent 直接控制该标签，不能承诺账号级隔离。

`agentInputUntil` 同时用于 USER_ACTIVE 抑制与文件选择框归因，不能整块删除。拆成动作来源归因与近期人工活动提示两种职责；前者从实际输入派发及有界宽限得出，不能以“当前操作仍存在”判断来源，否则长期隔离会把人工文件框误归为 Agent。后者只作尽力提示。明确交接承担确定约束，不把不可靠的时间窗包装成权限锁。

## 元素操作与成熟方案取舍

保留现有 ref、OOPIF 解析和坐标换算。在元素操作边界建立一份必要检查：元素连接状态、当前布局、目标点是否被其他元素遮挡，以及动作需要的 enabled/editable 状态。检查失败在输入派发前结束；只允许在尚未派发输入时作有界等待，不重复点击来确认成功。坐标输入继续按指定位置执行，不能套用不存在的元素身份保证。

本次不把原生 select 的脚本事件或整段 insertText 一律替换为逐字模拟；只有控件兼容性测试证明不足时才调整具体语义。使用 Playwright 的 actionability 原则校验边界，但不复制其整个定位和等待实现。

整体接入 Playwright 是另一条可选路线，当前不选：需要验证其页面接管、默认覆盖、目标管理与现有 debugger/弹窗链能否统一。若后续必须提供通用 Locator 能力，应先做替换原型，通过后删除被取代输入实现；不能同时让两套执行器管理同一页面。

## 文件加减法与影响范围

| 位置 | 增加或替换 | 删除或保留 |
| --- | --- | --- |
| electron/main/app.ts 与 browser-session.ts | 启动前统一默认 UA | 删除 Session UA 覆盖；保留网站分区、权限、下载 |
| electron/main/window.ts | 应用 Session 局部缓存配置及同源权限装配 | 删除全局禁用缓存函数和启动调用 |
| browser/operation.ts | 一个具体操作生命周期实现 | 不配接口、工厂、注册表或排队服务 |
| browser-tab.ts 与 input/session.ts | 绑定执行上下文，记录真实输入单元阶段 | 替换散装的无取消能力传递；删除旧完成推断路径 |
| cdp-session.ts 与 deadlines.ts | 区分底层命令落定、调用停止等待及回复预算 | 保留单一总时限，不将包装 Promise 的拒绝视为命令终止 |
| input/actions.ts、keyboard.ts、pointer.ts 等 | 通过同一上下文发命令和收尾 | 不在各动作添加独立时限与重试循环 |
| browser-host.ts、tab-log.ts | 回执与观察分开，单点提交观察基准 | 删除快照失败覆盖回执的路径与重复结果状态 |
| wire 与后端 browser/display | 同步新执行回执和观察契约 | 删除旧步骤结算字段及其分支，不保留兼容层 |
| 后端 browser/host_request.py 与宿主 params/methods | 请求级交接约束、实际目标一次检查 | 不复制 handoff_registry，不新增持久锁 |
| 前端工具步骤卡片 | 显示完成、中断及结果不确定，继续复用页面入口 | 不增加指纹设置面板或单独风控仪表盘 |

开发界面切换 Session 会一次性重置该界面的本地偏好；网站登录数据、数据库、Run 恢复和 Task 归属不变。工具输入原则上保持现有用户能力；内部请求上下文、工具输出与 UI 展示有意改变并一次迁移。

## 分阶段实施与验收

### 阶段一 环境来源收敛

完成 UA 单源及缓存局部化。验收普通页、window.open、target blank、重定向、同源与跨站 iframe、worker 的请求和页面可见信息；开发与打包环境分别覆盖。验证 Vite 原问题、网站缓存和登录保留。保留原生 Electron 探针作为环境测试入口，复用项目打包能力，不依赖 Playwright 默认接管。

### 阶段二 执行和结果契约

操作生命周期、取消、输入收尾和回执拆分作为同一阶段交付，不能只接 signal 后仍沿用误导性结果。

- 首次 keyDown 后取消：不派发后续字符及尚未开始的 submit 回车；当前输入单元按明确定义收尾。
- 点击按下、拖动中、按键中弹窗：答复控制路径不被占用阻断，原取消批次不恢复后续输入。
- 动作成功后注入快照失败、标签自关闭：已知步骤回执仍保留，观察结局正确。
- 调用取消或超时后旧命令迟到：不能与新 Agent 修改交错，不能推进未返回的增量基准。
- 状态无法确认：回复预算内返回未知，已超时或取消则后续状态可见；停止新 Agent 修改和复用标签导航，用户能关闭并新建标签，不无限等待或自动重放。
- wire 样例、后端正文和前端步骤卡片表达一致，业务提交成功不从输入回执推断。

### 阶段三 用户边界与元素可靠性

交接期间用新消息唤醒 Run，验证修改目标被拒、只读可用、用户交还后恢复；覆盖省略 tab、切换 current、close、新建、后端重启和标签自关闭。验证真实用户导航中止旧操作及文件选择框归因不退化。

用本机页面覆盖遮罩、禁用、readonly、动画、跨框架、缩放及坐标画布。目标是输入前拒绝错误操作，不以更多重试掩盖失败。保留原生 select、IME、contenteditable 的兼容性回归。

每阶段通过定向单测、契约守卫和相关桌面用例后再进入下一阶段。正常路径复用已有测试，只有新生命周期分支和已复现缺陷新增回归。不要为纯包装层编写镜像测试。

## 日志与文档

复用 `logDesktopEvent` 记录操作开始、停止、未知结果、清理结局和观察失败，携带 Task、标签和已有调用标识。日志仅作诊断，不充当执行状态或交接事实源，不新建审计数据库。

实施时更新 `docs/plan/embedded-browser-p3-discussion.md` 中被替换的当前行为说明，明确历史实测适用版本；本方案跟踪最终结构和验收结论。AGENTS.md 只更新稳定的取消、回执和事实归属边界，不写字段清单与算法。同步收窄工具描述中“用户正在这个页面上操作时会被拒绝”的承诺，修正中断步骤一律显示失败、动作触发弹窗一律计完成的表达。

## 本次刻意不做

- 不随机 UA、Canvas、WebGL、鼠标轨迹或键盘时序，不新增 stealth 脚本。
- 不改成多账号隔离产品，不增加代理、Profile 或账号管理。
- 不因可观察差异就移除弹窗 preload、焦点模拟或视口能力；替代方案通过原生测试后才可删除旧实现。
- 不建设全域限流器或验证码识别器；当前没有对应网站流量证据支持这些额外机制。
- 不扩展 host-link 为可靠消息队列，不承诺取消回滚、跨重启回执恢复或强一致跨进程锁。

## 外部依据

- [Electron app.userAgentFallback](https://www.electronjs.org/docs/latest/api/app#appuseragentfallback)：官方提供的应用默认 UA 来源，要求尽早设置。
- [Electron Session](https://www.electronjs.org/docs/latest/api/session#sessionfrompartitionpartition-options)：Session 缓存策略在首次创建时确定。
- [Playwright actionability](https://playwright.dev/docs/actionability)：操作前验证可见、稳定、接收事件、可用或可编辑等条件。
- [Playwright connectOverCDP](https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp)：接管既有浏览器有独立契约与默认设置，不能当成无副作用的输入函数替换。
