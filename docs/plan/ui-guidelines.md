# UI 视觉风格指南（coding-agent 桌面端）

> 本文档是前端视觉方向的**单一事实来源**，与 `apps/desktop/src/index.css` 的主题令牌、
> `tailwind.config.ts` 的颜色映射保持一致。组件实现必须经由令牌，不得硬编码视觉值
> （状态语义色 `success`/`warning`/`destructive` 除外，见 §4）。
>
> 本文件为 AGENTS.md 引用的视觉方向文档的落地版；AGENTS.md 中"参考 Codex 桌面客户端"
> 的表述以本文档的克制基调为准——Codex 的克制、低干扰质感才是目标，而非其对话气泡化外观。

## 一、设计立场（为什么要克制）

coding-agent 是开发者**每天长时间盯守**的工程装备，不是消费级聊天产品。UI 的职责是
"退到后台、不打扰思考"：像编辑器 / 终端 / 差异查看器那样安静。视觉噪声每多一分，就多一分
对注意力的抢夺。因此本项目的视觉优先级是：

1. **信息密度 > 装饰**：同样的屏幕要容纳更多有用的工程信息（日志、事件流、时间线）。
2. **中性灰阶为主，强调色稀缺**：颜色是"信号"不是"皮肤"。绝大多数界面元素是灰阶；
   彩色只出现在"需要立刻被注意的状态/动作"上。
3. **扁平 > 浮起**：用细边框划分区域，不用阴影制造层次。阴影=视觉重量，能免则免。
4. **小圆角 / 近直角**：圆角是"友好产品"的语言；工程工具用 2–4px 或直角更冷静。
5. **动效克制**：过渡存在但不抢戏；无不必要的弹跳、无装饰性动画。加载/思考指示用
   最低存在感的方式表达。

## 二、色彩系统（浅色 · 灰阶克制）

### 2.1 中性灰阶（主体）
- 背景 `--background`：近白但非纯白，略带冷灰（`0 0% 100%` 白可，但卡片/侧栏用更低的
  明度层级制造微弱纵深，避免纯平）。
- 前景 `--foreground`：近黑冷灰（`222 47% 11%` 量级），不用纯黑。
- 边框 `--border`：低对比细线（`214 20% 88%` 量级），用线分隔而非用块。
- 静音文字 `--muted-foreground`：中灰（`215 12% 42%` 量级），弱化次要信息。

### 2.2 强调色（稀缺使用）
- 主操作 `--primary`：**低饱和、近中性**的蓝或石板蓝（如 `215 28% 45%` 量级），
  **不**用 shadcn 默认高饱和蓝 `221 83% 53%`。主按钮仍是"唯一的彩色实心元素"，
  但饱和度压到一眼不跳。
- `--primary-foreground`：白或近白。
- `--ring`：与 `--primary` 同色系、降透明度，聚焦环细且弱。

### 2.3 状态语义色（保留，且必须语义清晰）
- `--destructive`：克制的红（`0 62% 50%` 量级），仅用于破坏性/失败。
- `success` / `warning`：通过组件层 `emerald-*` / `amber-*` 低饱和浅底表达（语义信号，
  不令牌化、不去掉，但底纹用 100 明度档的低饱和色，避免鲜艳）。
- 约束：状态色只在"状态徽章 / 终态指示"出现；不得用于普通装饰。

## 三、形状与层次

- 圆角 `--radius`：**0.25rem（4px）**。按钮/卡片/气泡/输入统一收窄；局部小元素可用
  `sm`（`calc(--radius - 2px)` ≈ 2px）。不使用 8px+ 的大圆角。
- 阴影：**默认无**。令牌层不提供 `shadow`；组件层仅允许在"浮层（popover/tooltip 等
  脱离文档流的弹出元素）"使用极轻阴影以区分层级，面板/卡片/按钮一律无阴影。
- 边框：区域划分优先用 `--border` 细线；hover 态用 `--accent` 浅底而非阴影或描边加粗。

## 四、组件视觉契约（实现约束）

- **Button**：`default` 变体 = 低饱和 `--primary` 实心、无 `shadow`；`outline`/`secondary`
  无 `shadow`；hover 用 `--accent` 浅底。不得恢复 shadcn 默认 `shadow`/`shadow-sm`。
- **Badge**：`default` 随 `--primary`（低饱和）；`outline` 仅文字无底；`success`/`warning`
  保留低饱和浅底语义色（见 §2.3）。
- **Card / Popover / Input**：无阴影（popover 浮层除外极轻阴影）；圆角服从 `--radius`。
- **状态徽章 / 终态**：状态色来自 §2.3，不引入新彩色。
- **禁用硬编码视觉值**：除 §2.3 状态语义色与 Radix 组件必需的 `--ring` 外，颜色/圆角/边框
  一律走 `index.css` 令牌 + `tailwind.config.ts` 映射，禁止在组件写 `bg-[#...]` /
  `rounded-[8px]` / `shadow` 字面类（既有违反项列入待清理，不在本轮令牌收敛范围）。

## 五、动效

- 过渡：`transition-colors` 允许，时长默认 ~150ms；不使用位移/缩放类装饰动画。
- 思考指示：`thinking-dot` 三点跳动保留但存在感最低（小、低透明），仅为"仍在处理"信号。
- 禁止：入场动画、列表项 stagger、按钮 press 放大等消费级动效。

## 六、与代码的关系

- 令牌唯一来源：`apps/desktop/src/index.css` 的 `:root` 块。
- 颜色映射唯一来源：`apps/desktop/src/tailwind.config.ts` 的 `theme.extend.colors`。
- 本指南与上面两份文件冲突时，以本指南为基调、同步修订那两份文件，不得让组件偏离本指南。
- 深色主题：当前未实现（无 `.dark` 定义）。未来若加，须同样遵循本指南的克制基调，
  而非引入高饱和深色皮肤。

## 七、验收口径（如何判断"够克制"）

- 整屏扫一眼：彩色面积 < 5%，主体是灰阶 + 细线。
- 主按钮是全屏唯一的实心彩色元素（且饱和度低）。
- 无卡片/按钮阴影（浮层除外）。
- 圆角统一 ≤ 4px。
- 状态色只出现在状态/终态，不出现在装饰。
