# Cosir 桌面窗口与托盘验收文档

**状态**：待实现、待验收  
**日期**：2026-09-09  
**对应方案**：[desktop-tray-lifecycle-design.md](desktop-tray-lifecycle-design.md)

> 本文是完成门禁，不是实现建议。没有证据的项目不得标记为“通过”；未实现或仅在单个平台验证，均不得宣称任务完成。

## 1. 验收对象与范围

验收对象为 `apps/desktop` 的 Tauri 桌面宿主，重点验证：

- 主窗口关闭按钮只隐藏，不退出应用。
- 托盘/状态栏图标可以恢复窗口。
- 右键菜单的“退出 Cosir”才真正退出。
- 隐藏窗口期间本机后端和 Agent run 不受影响。
- 单实例、后端恢复和退出清理不回归。
- Windows 和 macOS 的平台行为分别符合方案。

不验收新的 Agent 业务能力、Assistant Transport 字段、SQLite schema 或远程部署能力。

## 2. 通过规则

### 2.1 结果等级

| 等级 | 含义 |
|---|---|
| P0 | 硬门槛，任一失败即整体不通过 |
| P1 | 重要质量项，失败必须修复或由用户明确接受风险 |
| N/A | 只有在对应平台/发行形态不存在时允许使用，必须附原因和替代证据 |

### 2.2 总体门槛

整体“通过”必须满足：

- 全部 P0 为 `PASS`。
- P1 没有未解释的失败。
- 至少有一名独立子 Agent 审查实现与代码事实，并确认验收文档没有把未实现能力写成已完成。
- Windows 和 macOS 均完成平台验收；不能只用 Windows 结果推断 macOS。
- 发行包验收不可用时，状态只能是“阻塞/未完成”，不能是“通过”。

开始测试前确认：

1. 没有旧的 Cosir/Tauri/Python 后端实例残留。
2. 当前测试使用单实例启动入口。
3. 能够观察 Tauri 进程、FastAPI 子进程和必要的工具子进程。
4. 能够读取桌面日志，但证据中不得包含 API key、完整 prompt 或敏感文件内容。
5. 测试数据使用专用 workspace，不使用用户真实项目作为破坏性验证对象。

## 9.1 长运行测试夹具要求

W-12/M-08 不得依赖真实 LLM、外网或不可控的模型响应。验收前必须准备一个确定性的本地夹具（例如测试 provider/mock 或已有可控的本地慢任务），满足：

- 能明确产生 `runId`、`commandId` 和开始/完成状态。
- 至少保持运行状态 10 秒，给关闭窗口和进程快照留出时间。
- 在 60 秒内稳定完成，或返回可判定的失败结果。
- 完成后能通过现有 snapshot/Transport 读取到唯一结果。

若当前代码没有可重复使用的夹具，则 W-12/M-08 直接为 `BLOCKED`，不得用手工“看起来还在运行”代替。

## 10. 失败处理与证据要求

每个失败项必须记录：

```text
测试 ID：
环境：
复现步骤：
实际结果：
期望结果：
相关日志 event：
进程/端口证据：
是否影响 P0：
后续动作：
```

以下情况直接判定相关 P0 失败：

- 点击 X 后 FastAPI 或 Agent run 停止。
- 托盘无法恢复窗口。
- 没有明确的真正退出入口。
- 退出后留下 FastAPI、CodeGraph 或工具子进程。
- 二次启动创建第二个实例。
- macOS Cmd+Q 被错误地变成隐藏窗口。
- 仅在开发模式验证，发行形态没有结果却标记整体通过。

## 11. 独立子 Agent 审查记录

子 Agent 必须基于当前工作树实际代码完成审查，至少检查：

1. 方案中的进程拓扑是否符合代码事实。
2. 关闭和退出路径是否真的分离。
3. `RunEvent::ExitRequested`/`Exit` 是否存在重复清理或竞态。
4. Windows/macOS 条件编译、tray 资源和 Tauri capability 是否完整。
5. 验收项是否覆盖隐藏期间 Agent run、单实例、崩溃恢复和子进程清理。
6. 是否有任何“文档写了但代码没有”的虚假完成项。

记录格式：

```text
审查 Agent：
模型：gpt-5.6 Luna
审查时间：
审查结论：PASS / FAIL / BLOCKED
发现的问题：
必须修复项：
对方案或验收文档的修改：
```
