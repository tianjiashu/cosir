# 客户端 UI 指南

客户端 UI 参考 Codex 桌面客户端风格，但不做像素级复刻。

## 视觉方向

- 整体风格：浅色、克制、安静、工程工具感。
- 信息密度：偏高密度，适合长时间开发、阅读日志、查看任务状态和代码变更。
- 视觉语言：低饱和灰阶、细边框、轻阴影、少量强调色。
- 布局原则：分栏清晰，层级明确，减少装饰性元素。
- 交互原则：按钮少但明确，图标优先，必要时配合 tooltip。

## 基础布局

- 左侧栏：项目、任务、历史会话、插件/能力入口。
- 中央区：主会话、Agent 输出、计划、执行过程、总结。
- 右侧栏：Outputs、Sources、上下文引用、工具调用、审批信息。
- 底部输入区：用户输入、附件、审批选项、模型/模式选择、发送操作。
- 顶部区：当前任务标题、运行状态、轻量导航。

## 第一版客户端 UI 参考

第一版客户端 UI 参考 Codex 桌面客户端的三栏工作台形态，但不做像素级复刻。

核心布局：

- 左侧固定导航栏：应用入口、项目列表、任务列表、历史任务，当前项目和当前任务需要有明确选中态。
- 顶部轻量任务栏：显示当前项目或任务标题、项目图标、更多操作入口。
- 中央主会话区：展示用户消息、Agent 处理状态、执行结果、代码块、文件链接和总结。
- 右侧浮动或固定信息面板：展示 Outputs、Sources、上下文引用、生成文件、相关文档和工具产物。
- 底部输入区：固定在主会话底部，承载纯文本输入、权限状态、模型选择、语音入口占位和发送按钮。

第一版输入区只支持纯文本输入。图片、文档和附件卡片不进入第一版范围，但布局上可以保留添加入口或占位，不实现附件发送能力。

中央主会话区要求：

- 用户消息靠右或有明确气泡样式，Agent 输出在主流中按步骤展示。
- 长文本、方案摘要、命令输出和代码片段使用独立的浅灰代码块或内容块。
- 文件输出使用可点击文件链接样式，例如 `docs/agent-v1-technical-plan.md`。
- 运行状态需要可见，例如“处理中”“已处理 1m 32s”“已取消”“失败”。
- 工具调用状态需要可折叠，避免主会话被低价值日志淹没。

右侧信息面板要求：

- 第一版至少支持 Outputs 列表和 Sources 列表的视觉位置。
- Outputs 用于展示当前任务产生或修改的文件、文档、代码片段等结果。
- Sources 用于展示本轮任务引用的文档、上下文片段或规则文件。
- 右侧面板可以先做静态/只读列表，后续再接工具调用详情、checkpoint 和上下文引用。

左侧导航要求：

- 第一版至少展示项目列表和任务列表。
- 项目和任务标题要支持截断，不能因为长文本撑破布局。
- 当前任务需要清晰选中态。
- 底部保留用户信息、设置或帮助入口位置。

## UI 组件实现决议

- 主 UI 体系：`shadcn/ui + Radix UI + Tailwind CSS + lucide-react`。
- `shadcn/ui`：可复制、可定制的业务组件基础。
- `Radix UI`：Dialog、Popover、Tooltip、Tabs、Dropdown、ScrollArea 等底层可访问交互原语。
- `Tailwind CSS`：布局、间距、颜色、边框、状态和响应式样式。
- `lucide-react`：默认图标体系。
- `cmdk`：命令面板和快捷操作入口。
- `TanStack Table`：表格、任务列表、文件变更列表等结构化数据视图。
- `TanStack Virtual`：日志流、长任务流、长列表等虚拟滚动场景。
- `Monaco Editor`：优先用于代码、diff、patch、只读预览和编辑器区域；如后续确认体积或性能压力过高，再评估 `CodeMirror 6`。
- 不优先使用 Ant Design 或 MUI 作为第一版主 UI 体系。

## 组件原则

- 优先使用 shadcn/ui 和 Radix UI 构建可定制基础组件。
- 使用 Tailwind CSS 统一间距、边框、颜色、状态和响应式规则。
- 使用 lucide-react 作为默认图标体系。
- 长列表、日志、任务流、文件变更列表必须考虑虚拟滚动。
- 代码、diff、patch、只读预览使用专门代码编辑/展示组件，不手写简陋文本区。
- UI 必须服务工程工作流，不做营销式 hero、装饰卡片或大面积无效留白。
