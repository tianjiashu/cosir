# 客户端按文件拆分改造方案

## 文档目标

- 基于当前桌面客户端代码结构，给出一份面向实现的改造方案。
- 重点回答“哪些文件要改、职责如何收敛、为什么这样拆”。
- 不展开详细代码实现，只定义页面、store、service、shared 协议和日志边界的改造方向。

## 适用范围

本方案覆盖：

- 新建任务页面
- workspace 树与左侧 task 回显
- task 内多轮连续对话
- turn 级 SSE
- timeline 投影与 renderer 边界
- 客户端日志边界

本方案不覆盖：

- 附件、多模态、语音
- 完整审批交互按钮
- 最终视觉 polish

## 已确认约束

- 点击“新建任务”后，要进入专门的新建任务界面。
- 首次发送前需要先选 workspace。
- 一个 workspace 下可以有多个 task。
- 一个 task 下可以有多轮对话。
- 首条发送后要同时：
  - 创建 task
  - 创建首个 turn
  - 进入 task 对话页
  - 左侧栏立即回显该 task
- `stream` 围绕 `turnId`，不是 `taskId`。
- 左侧 workspace 支持折叠 / 展开。
- 删除 workspace 时要删除其下所有 task 记录。
- 第一版内部架构支持多 renderer，但 UI 先只实现：
  - `markdown`
  - `tool`
  - `status`

## 当前代码的主要断裂点

### 1. 任务心智仍然是“输入一次 = 创建一个新 task”

- [apps/desktop/src/hooks/useTask.ts](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/hooks/useTask.ts)
- [apps/desktop/src/components/layout/InputBar.tsx](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/components/layout/InputBar.tsx)

当前 `createTask(text)` 同时承担“首轮创建”和“继续追问”，直接导致第二轮对话错误地新建 task。

### 2. taskStore 仍然带着 session 心智

- [apps/desktop/src/stores/taskStore.ts](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/stores/taskStore.ts)

当前 store 仍以 `currentSessionId` 为主字段，不适合长期 `workspace / task / turn` 模型。

### 3. ChatPanel 直接渲染 raw event

- [apps/desktop/src/components/layout/ChatPanel.tsx](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/components/layout/ChatPanel.tsx)
- [apps/desktop/src/stores/eventStore.ts](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/stores/eventStore.ts)

当前聊天区是：

- 用户消息取 `activeTask.input_text`
- assistant 文本靠 `model_output_delta` 拼接
- tool/status 直接筛 raw event 渲染

这会导致 timeline 顺序不稳定，也让 UI 强耦合后端内部事件结构。

### 4. Sidebar 仍是静态 mock 结构

- [apps/desktop/src/components/layout/Sidebar.tsx](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/components/sidebar/ProjectList.tsx)
- [apps/desktop/src/components/sidebar/TaskList.tsx](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/components/sidebar/TaskList.tsx)

当前左侧还停在“静态项目 + 静态任务”模型，和已确认的 workspace 树、多 task、多轮回显目标完全不匹配。

### 5. SSE 仍然围绕 task

- [apps/desktop/src/services/sse.ts](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/services/sse.ts)
- [packages/shared/ts/api.ts](/Users/woaigugu/Documents/coding-agent/packages/shared/ts/api.ts)

当前流连接仍是 `GET /tasks/{task_id}/stream`，不符合 turn 级长期协议。

### 6. 标题与诊断链路仍然直接依赖 task 的单轮输入

- [apps/desktop/src/components/layout/TopBar.tsx](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/components/layout/TopBar.tsx)
- [apps/desktop/src/components/right-panel/ConversationTraceBlock.tsx](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/components/right-panel/ConversationTraceBlock.tsx)
- [apps/desktop/src/stores/conversationTraceStore.ts](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/stores/conversationTraceStore.ts)

当前标题仍直接展示 `activeTask.input_text`，诊断链路仍把流请求记录成 `task_stream`、按 `taskId` 索引，和 turn 级新协议不一致。

## 文件级改造方案

## 一、根布局与页面流

### 1. [apps/desktop/src/App.tsx](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/App.tsx)

**当前职责**

- 组装三栏工作台布局
- 在 chat / logs 两个视图之间切换

**需要改什么**

- 从“一个 chat 页面”升级成更明确的主区状态流：
  - workspace 空状态
  - 新建任务页
  - task 对话页
  - logs 页
- 主区视图不再只靠 `activeView: chat | logs` 表达。
- 需要引入“当前页面模式”与“当前选中的 workspace / task / turn”之间的明确关系。

**为什么这样改**

- 根组件必须先表达页面流，下面的 Sidebar / InputBar / ChatPanel 才不会继续互相抢职责。

**不建议做什么**

- 不要把“新建任务页”做成在 `InputBar` 里硬编码分支，那样会让布局层与输入层继续耦合。

### 2. 建议新增 `apps/desktop/src/pages/chat/NewTaskPage.tsx`

**职责**

- 只负责：
  - 选择 workspace
  - 输入首条消息
  - 触发“创建 task + 创建首个 turn”

**为什么新增文件**

- “新建任务”已经是明确页面，不应继续塞在 `InputBar` 或 `ChatPanel` 内。

### 3. 建议新增 `apps/desktop/src/pages/chat/TaskConversationPage.tsx`

**职责**

- 只负责展示某个 task 的连续 timeline、底部输入区、当前 turn 的运行状态。

**为什么新增文件**

- 把“task 对话页”和“workspace 空状态 / 新建任务页”拆开，页面流才稳定。

## 三、输入与任务创建 / 继续对话

### 10. [apps/desktop/src/components/layout/InputBar.tsx](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/components/layout/InputBar.tsx)

**需要改什么**

- 不再直接等价于“创建新 task”。
- 其行为必须由页面上下文决定：
  - 在新建任务页：发送 = 创建 task + 首个 turn
  - 在 task 对话页：发送 = 给当前 task 追加新 turn
- 保留本地用户消息回显，但不自己决定对话容器类型。

**为什么这样改**

- 输入框是动作入口，不是产品状态机本身。

### 11. [apps/desktop/src/hooks/useTask.ts](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/hooks/useTask.ts)

**需要改什么**

- 从单一 `createTask(text)` 升级为更清晰的动作集合：
  - 创建 workspace 下 task
  - 给已有 task 创建 turn
  - 加载 task 详情 / 历史
  - 连接当前 turn stream
- `createTask` 不应再自动代表“唯一发送动作”。

**为什么这样改**

- 当前 hook 已经承担了“创建 + 连接流 + 清空事件 + 切活跃任务”的组合副作用，需要拆清楚。

**后续建议**

- 后续可继续拆成：
  - `useCreateTask`
  - `useCreateTurn`
  - `useTaskHistory`

### 12. [apps/desktop/src/hooks/useSSE.ts](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/hooks/useSSE.ts)

**需要改什么**

- 当前真正被组件调用的是 `connect(taskId)` / `disconnect()`，这里必须改成 turn 级连接心智。
- `connect()` 的输入边界要从 `taskId` 切到 `turnId`，并同步日志上下文与 trace 记录方式。
- 连接实例生命周期仍可保持单连接策略，但主键必须从 task 改成 turn。

**为什么这样改**

- `services/sse.ts` 只负责底层连接，真正把它接到 React 生命周期的是这个 hook；漏掉这里，turn stream 无法落地。

## 四、状态管理层

### 13. [apps/desktop/src/stores/taskStore.ts](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/stores/taskStore.ts)

**需要改什么**

**为什么这样改**

### 15. 建议新增 `apps/desktop/src/stores/turnStore.ts`

**职责**

- 管理：
  - 当前 task 下 turn 列表
  - activeTurnId
  - turn 状态

- turn 是新的实时运行主边界，不应该继续被 eventStore 隐式代理。

### 16. [apps/desktop/src/stores/eventStore.ts](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/stores/eventStore.ts)

**需要改什么**

- 从“当前任务事件数组”升级为更明确的 runtime event 事实存储。
- 不能只围绕单个 active task 工作。
- 需要支持：
  - 按 task 聚合历史事件
  - 按 turn 追加实时事件
  - 基于 event_id / sequence 去重

**为什么这样改**

- eventStore 应是事实源，但不能继续直接承担 UI timeline 结构。

### 17. 建议新增 `apps/desktop/src/stores/timelineStore.ts`

**职责**

- 保存投影后的 timeline items。
- 提供按 task 读取、按 turn append 的稳定渲染模型。

**为什么新增文件**

- 避免继续让 `ChatPanel` 自己从 raw events 临时拼 UI。

### 18. [apps/desktop/src/stores/conversationTraceStore.ts](/Users/woaigugu/Documents/coding-agent/apps/desktop/src/stores/conversationTraceStore.ts)

**需要改什么**

- 当前 `operation` 里仍是 `task_stream`、按 `taskId` 建立 stream trace 索引。
- 改造后要能表达：
  - task 创建请求
  - turn 创建请求
  - turn stream 请求
- 诊断索引不能继续只按 task 粗暴覆盖，至少要明确当前活跃 turn 对应的 stream trace。

**为什么这样改**

- 这是右侧诊断面板和日志入口的状态事实源，不跟进 turn 语义，排查链路会继续漂移。

## 客户端验收标准

- 点击“新建任务”会进入专门的新建任务页面。
- 新建任务页必须先选 workspace，再输入首条消息。
- 发送首条消息后会创建 task、创建首个 turn、进入 task 对话页。
- 左侧 workspace 树下会立即回显该 task 条目。
- 同一 task 下第二轮发送不会创建新 task，而是创建新 turn。
- task 历史消息、tool、status 会连续保留，不会清空。
- SSE 连接围绕 `turnId`，不是 `taskId`。
- ChatPanel 最终消费的是 timeline 投影，而不是 raw event 直接渲染。
- 新增日志点遵守日志规范，客户端继续通过统一日志出口落盘。
