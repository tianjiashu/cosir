但做到现在，我产生了一个梦想，于是产生了一个项目愿景，打造一个真正的Coding-Agent，来实现编码任务。

QA：
- Q:为什么要做Coding-Agent？
- A: 首先Coding-Agent 有真实的场景，有成熟的评测指标，有成熟的实现，本人又是码农出身，所以我想实现一个真正的Coding-Agent，来实现编码任务。

- Q: 什么事真正的Coding-Agent？
- A: 我认为真正的Coding-Agent 或者是说我想做的Coding-Agent 应该区别于非开发人员使用的以VibeCoding为导向的Coding-Agent，面向专业的开发人员的Coding-Agent。
代码文件本就是结构化数据，任何代码文件都可以被解析为结构化数据，它不应该像处理文档一样来处理，每个开发语音都有自己语法树，是结构化的数据。
搜索代码文件，应该基于语法树来搜索，而不是基于文本来搜索。
目前很多Coding-Agent的搜索功能都是基于文本来搜索，而不是基于语法树来搜索。
 
在日常观察到，很多Coding的能力很多都是基于Agent的主动能力：
比如：
lint检查、编译检查，它通常以tool的形式来供Agent调用，但是我认为它应该是被动的能力，Agent每写完一个代码文件，应该自动进行lint检查、编译检查，反馈给Agent修改
文本编码，比如utf-8、gbk、big5 等，Agent应该自动根据文件内容来判断编码类型，而不是在写入文件时自动兼容，对Agent来说透明。
初始检索代码位置可以基于文本的形式搜索，但是后续去看代码的执行链路，应该基于语法树来搜索。现在Agent大多还是依赖文本搜索+Agent理解。
代码开发形式，Agent很多行为还是补丁式开发，而不敢结构化重构。首先，针对项目不同开发周期，开发风格是不同的。项目没有上线初期，开发风格应该是敢代码重构，敢推翻重建，只为了项目可长期迭代维护。
项目上线后，有了一定用户量，开发风格应该是基于现有代码架构做最小改动，实现需求工程，风险最小化。（我知道现在可以通过Skill、插件来弥补，但我认为这是一种兼容，好的Coding-Agent应该是最佳实践）
还有各种开发工具，应该是Coding-Agent 自带的或者插件式的，比如死代码检测，现在已经有死代码检测工具，不应该依靠Agent主动扫描、判断。
